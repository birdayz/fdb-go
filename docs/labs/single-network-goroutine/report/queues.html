1. Writer Queue Designs Evaluated

Four Queue & Handoff Architectures

  1. D-NG (FDBGO_NET_DESIGN=ng) — Mutex + Byte Slice Swap: Senders encode into a pooled frame buffer, lock w.mu, append bytes to w.q, and unlock. Only the sender that transitions len(w.q) from 0 → >0 signals the 1-buffered w.sig channel (mirroring C++ Peer::send's firstUnsent check). The writer swaps w.q with a spare buffer under w.mu and issues a single conn.Write(buf).
  2. D-NG-chan (FDBGO_NET_DESIGN=ngc) — Buffered Channel Writer: Senders push chanFrame{bufp, frame} onto a buffered channel (cap=4096). chanLoop blocks on the first frame, drains len(ch) additional frames into a contiguous buffer, returns the pooled frame buffers, and calls conn.Write(buf).
  3. D-NG-ring (FDBGO_NET_DESIGN=ngr) — Lock-Free MPSC Byte Ring + writev: A 1 MiB power-of-two ring with 4,096 slots. One 64-bit CAS on reserve claims seq16<<48 | pos48 simultaneously. Senders encode directly into the ring slice in place and store slot.ready = seq + 1. ringLoop scans consecutive ready slots and writes them with a single writev(2) via net.Buffers.WriteTo.
  4. D-M / M (FDBGO_NET_DESIGN=m) — Sender-Writes (No Writer Goroutine): A sender that wins wmu.TryLock() writes its own frame directly on its caller goroutine, then drains any frames other senders appended to pending while the write was in flight.

Why Lock-Free Ring v1 Collapsed at 73k ops/s — and Why v2 Still Doesn't Beat a Mutex

  • v1 failure mode (in-order commit spin): Our first Disruptor-style MPSC ring reserved a byte span with atomic.AddUint64 and required each sender to spin on committed.Load() == start before advancing committed = end. At 256 workers across 8 Ps (32 goroutines/P), if the OS or Go scheduler preempted a sender in the ~40 ns window between reservation and commit, every subsequent sender on that connection spun in runtime.procyieldAsm. Throughput on get100/256 collapsed from 256.9k to 73.1k ops/s, client CPU tripled from 27.0 to 84.8 µs/op, and cpu.pprof showed 25.7s (12.7%) in procyieldAsm + 41.2s (20.3%) in runtime.lock2.
  • v2 fix (per-slot ready + writev): Packing seq16<<48 | pos48 into one CAS and publishing per-slot ready removed all sender-to-sender waiting. Throughput jumped from 73.1k to 243.0k ops/s (29.3 µs/op), and raw write syscalls dropped to 0.01/op (replaced by writev).
  • Why D-NG (257.7k ops/s, 27.0 µs/op) still beats both: As the pprof mutex profile below proves, the send-queue mutex w.mu in naSend + naLoop accounts for only 0.16% of CPU time and 1.20% of lock contention! Removing a 40 ns uncontended lock around a slice append saves nothing, while ring slot management and writev iovec construction cost slightly more CPU than one contiguous Write.

2. Deep Dive on D-M (M): Speed vs Socket Backpressure Failure (T1/T2)

Why D-M was built and tested: D-M removes the per-connection writer goroutine completely so we can measure the exact cost of having a dedicated writer goroutine vs writing on the caller's goroutine under a lock.

Happy-Path Performance (When Sockets Never Fill)

  • On loopback when the kernel socket send buffer never fills, write(2) is a fast copy into kernel memory and never blocks.
  • On Box 2 (rawhz5), D-M achieved 260.8k ops/s on get100/256 (21.3 µs/op) and 48.5k ops/s on get100/64 (55.6k ops/s at GOMAXPROCS=4, halving client CPU from 47.5 to 24.1 µs/op).
  • On netg-r6 (rawhz6, where D-M and D-NG ran side-by-side in the same rotated rounds), D-NG matches or slightly leads D-M across the board, proving that the dedicated writer goroutine in D-NG costs nothing in throughput or latency once the write-ack rendezvous and hrtimer are removed.

Why D-M Fails T1 and T2 Under Backpressure

  • Violates T2 (ctx is local): When a TCP socket send buffer fills (slow peer, network partition, or large commit burst), the caller goroutine that won wmu.TryLock() blocks inside the kernel write(2) syscall writing both its own frame and every frame queued behind it. Its ctx cancellation cannot interrupt the blocking write unless the whole connection deadline is poisoned.
  • Violates T1 (no write acknowledgment): The lock holder cannot return to its caller until the kernel accepts the entire drained queue — turning enqueue into a synchronous write barrier for the whole batch.
  • 10 deterministic -race failures in pkg/fdbgo/client (race6-m-*):
    • TestNativeCommit_ReplyBeforeWriteAcknowledgment (4 subtests): commit reply arrives before the committing sender returns from its blocked write.
    • TestNativeCommit_WriteBackpressureOwnerRetirement (4 subtests): native actor cannot exit while blocked in gated socket writer.
    • TestFallbackStartsEndAtTransportSuspension/flush & TestFallbackReadyBeginStartsEndBeforeConsumingError: warm fallback request is serialized behind a blocked flush.
  • Why curing D-M recreates A: Using non-blocking write(2) and handing unwritten EAGAIN tails to a background goroutine is literally today's rawWriter + writeLoop tail-handoff machinery in A.
