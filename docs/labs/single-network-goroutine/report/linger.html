1. How Coalescing Linger Moves Client Latency, Batching & Server Cost

What we swept:
  • Fixed linger on D1 (FDBGO_NET_DESIGN=1): 0 µs (D-NG), 5 µs (D5), 10–20 µs (D, the C++ MIN/MAX_COALESCE_DELAY), 50 µs (D50), 100 µs (D100), and 250 µs (D250).
  • Nagle-style adaptive linger (FDBGO_NET_DESIGN=nga): D-NG-adap20 (20 µs window) and D-NG-adap100 (100 µs window). If the previous write on this connection was ≥ W ago, the writer flushes immediately (zero delay on an idle connection); if a write just happened within W, the writer yields with runtime.Gosched() (no kernel hrtimer syscall) until lastWrite + W, coalescing bursts while avoiding timer overhead.
  • Post-write yield (D-NG+yield, FDBGO_NET_DESIGN=ngy): calls runtime.Gosched() once after each socket write before checking the queue again, mirroring the commented-out yield(TaskWriteSocket) in FlowTransport.actor.cpp.
