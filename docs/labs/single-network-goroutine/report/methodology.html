2. Differential Server-Cycle Measurement & Anti-Bias Protocol

Short-Minus-Long Differential (run_cell.py)

  • Every arm measurement in every round executes two full clientbench runs under perf stat -p <fdbserver_pids> -e task-clock,cycles,instructions: a short run (Nshort iterations + 5% warmup) and a long run (Nlong = 3 × Nshort iterations + 5% warmup).
  • Server cycles per transaction is computed as (cycleslong - cyclesshort) / (txlong - txshort), canceling process startup, connection dial/handshake, initial key-location warmups, and fixed per-run background ticks.
  • Client metrics (ops/s, p50, p99, getrusage user+sys CPU/op, Go heap allocs/op) come from the steady-state measurement window of the long run (after warmup).

Rotated Round Ordering & Foreign-CPU Guard

  • Order rotation (ladder.sh): In round r, the arm list is cyclically shifted by r × (N/2 + 1) mod N and reversed on odd rounds, preventing warm-cache or storage-engine compaction drift from favoring any arm.
  • Foreign-core guard: Around every run, run_cell.py snapshots /proc/stat busy jiffies on CPUs 2–15 and subtracts the client's RUSAGE_CHILDREN CPU time plus the fdbserver PIDs' /proc/<pid>/stat jiffies. Any run where foreign processes consume above the threshold is automatically rejected and re-run.
  • Box-to-box calibration:Running identical binaries on Box 1 (`rawhz4/cross`) and Box 2 (`rawhz5`) showed that while L on set100/64 is within 3% (`18.6k` vs `19.2k` ops/s, `70.4` vs `72.0` kc/tx), latency-sensitive get100/64 varies by up to 25% across cloud hypervisor placements (`A`: `47.4k` vs `36.0k`). Therefore, all comparisons are strictly paired within the same box and rotated round.
