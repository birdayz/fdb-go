# R18 offline descriptive analyzer

## Staging and invocation

Stage these files before preparation freezes the common input map:

```text
fullstack-r18-build/
  analyze-r18.py
  analysis-support/
    r16_trace_parser.py
    frozen-v7-scripts/
      analyze.py
      run.py
      r3_plan.py
```

The helper files are unchanged copies. `r16_trace_parser.py` SHA256 is `9bafafddd9f8f7dfd9464283265512933d6e811be09130769bb987860a93f1c0`; it is the parser previously exercised and audited against sealed R16 traces. Frozen V7 script hashes are checked before import. Acquisition/analyzer main functions in these helpers are never invoked.

```sh
python3 -B /opt/fdbperf/artifacts/fullstack-r18-build/analyze-r18.py \
  /opt/fdbperf/artifacts/fullstack-r18 \
  /opt/fdbperf/artifacts/fullstack-r18-analysis
```

The output must not exist and must be outside the input tree. `--v7-scripts PATH` can relocate only the frozen V7 scripts; their hashes remain fixed. The trace parser stays in `analysis-support/` next to the analyzer. The preparation script recursively pins these helper Python files, and the analyzer requires its own bytes and the trace parser to occur in the common pin map.

Registration is fixed to `R18-preregistration-v1.md`, SHA256 `8fb5c623fc8dbe81d71e6cada2cf66ac2292362464466543e95650c52b229698`. No registration, source, binary, or library identity is silently substituted.

## Populations and validation

The global six-block schedule is independently regenerated by frozen `make_schedule`, seed798001. Only output paths are normalized for this comparison. All six arm orders must occur. Each `runNNN` is validated as a single-entry `execute` artifact, not falsely treated as a complete V7-main campaign. Per-entry plans may differ from the global plan only in the declared GOMAXPROCS environment selection and `selected_run_index` metadata.

All18 uninstrumented processes and both separately acquired traces must validate before results are written. Raw count/index/byte checks, zero callback retries/errors, backend/source identities, exact integer A–E counters, lifecycle fixpoints, pre-pinned plans/commands, prefix uniqueness, serial ordering, and frozen pre-run quiescence gates are checked. During-run telemetry is preserved, not turned into new rejection thresholds.

- Timings: go8/go2/cgo, read1000,5000 measured+200warmup. Only these18 processes enter latency/CPU comparisons.
- Traces: go8 then go2,200 measured+200warmup after timing completion. Exact unique chronological getrusage A–E signatures locate phase entry counts. No trace latency/CPU comparison is computed.
- Trace whole-process counts are raw only. Only measured-window entry counts are divided by200.
- Thread comm observations are preserved; an empty observation file is reported as no observations, never as an inferred runtime role.
- The trace timeline carries boundary-overlap/reference-marker flags, original file/line references and a separate raw sample reference. No exact per-transaction alignment is claimed.

## Outputs

`TABLES.md` and `analysis.json` report all three paired comparisons: go2/go8, go8/cgo and go2/cgo. For every metric they retain all six ratios, their geometric mean, and observed minimum/maximum. These ranges are **not confidence bounds**. No bootstrap, confidence interval, hypothesis test, equivalence claim or shipping recommendation is produced.

- `timing-per-run.csv`: all18 process statistics, A–E counters, lifecycle/GC records, identity/configuration and raw-file hashes.
- `timing-per-block.csv`: all six paired block values and ratios per comparison/metric.
- `timing-descriptive.csv`: six-ratio lists, geometric means and observed ranges.
- `timing-absolute.csv`: six individual arm values plus median/range; absolute E/N is unpaired only.
- `trace-phase-entry-counts.csv`, `trace-wholeprocess-counts.csv`: separate go8/go2 trace populations.
- `strace-sequence/{go8,go2}/`: marker evidence, per-TID/aggregate counts, overlaps, merged JSON/CSV/text timeline and thread-name references.
- `provenance.json`, `input-files.csv`, `status.json`: provenance and explicit complete/failed status.
- `raw/`: unchanged copy of every input file, verified against the input SHA256 inventory.

Window CPU is C-B; drained is D-B; shutdown-inclusive is E-A. E-A includes startup, fixture, warmup, validation, CSV, forced GC and shutdown, not isolated steady-state CPU; it excludes preceding identity hashing, final JSON and process exit. Absolute E/N is never paired. Go allocation counters exclude native C++ heap.

Results concern the registered workloads on the reimaged existing instance, not independent host replication. No R17 observations are pooled, and R18 cannot rescue an R17 endpoint or establish repository correctness/review/CI approval.

## Offline selfcheck

```sh
python3 -B /path/to/work-fullstack-r18/selfcheck-r18.py
```

Uses only synthetic artifacts. Checks six-block GM/ranges, all individual ratios, no pair exclusion when a log ratio is undefined, no absolute-E pairing, short-run/timing separation, exact marker matching, split unfinished/resumed calls, carry-in/out, unknown terminal ends and ambiguous-marker rejection. AST-extracted acquisition validation is exercised against five valid timing/trace fixtures and110 invalid mutations. No acquisition top-level code, subprocess, VM, network or repository test/build runs.
