The first extension of analyze-queue-wait.py to the reclaim arm rejected a real zero with its earlier assertion that both callers and drainer must have positive sampled contention. Reclaim get100 had 5,428,823 ns queue contention, all schedule/remove, and no sampled drainer contention. Cleanup can empty the heaps before the runtime wake. The validator now requires nonempty completed benchmark population, positive total queue wait, and identified exact queue-unlock source lines, but allows a zero category. No workload run was discarded or rerun for this analysis correction. Original assertion output was retained in the tool transcript; raw pprof files are unchanged.
