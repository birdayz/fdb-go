fdb-go v0.2.0 is the first release since v0.1.0. It moves the Java target to Record Layer
4.14.2.0 and changes SQL storage, so read **Upgrading from v0.1.0** before pointing it at existing
data. The full list is the `v0.2.0` entry in [CHANGELOG.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/CHANGELOG.md).

**Upgrading from v0.1.0**

- **SQL storage changed; nothing migrates automatically.** The relational key space is Java's
  `RelationalKeyspaceProvider` layout byte for byte, so Go and Java open each other's databases and
  schemas, but SQL data written by v0.1.0 is not readable. Recreate it, or export and re-import it
  as described in [docs/upgrade.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/upgrade.md).
- A database path is `/DOMAIN/DATABASE`, as in Java. Register the domain once per process before
  use: `sqldriver.RegisterDomainIfNotExists("FRL")`.
- `FDBDatabase.Run` and its variants retry the way Java's transaction runner does: at most 10
  attempts by default (`FDBDatabase.SetMaxAttempts`). A body that commits the context it was handed
  is refused.
- Go API packages moved to follow Java's: `pkg/recordlayer/indexpredicate`,
  `pkg/recordlayer/query/plan/plans`, `pkg/async/rtree`. `keyspace.FDBResolver` is removed.
- `frl` is a package of the root module. `go install fdb.dev/cmd/frl@latest` installs this release;
  the old nested module `fdb.dev/cmd/frl` is retracted.

**What changed**

- **Java Record Layer 4.14.2.0** is the target for wire format and SQL behaviour. Records Java writes
  through `TransformedRecordSerializer` (compressed, encrypted) are read and written, and HNSW graphs
  are written byte for byte as Java writes them. The remaining exceptions are listed in
  [docs/compatibility.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/compatibility.md).
- **SQL follows Java 4.14.2.0** across the query surface: EXISTS in boolean expressions, recursive
  CTE typing and naming, case-sensitive identifiers, `LIKE`, comments, `COALESCE`/`GREATEST`/`LEAST`,
  QUALIFY with aggregates, `UPDATE`/`DELETE … RETURNING`, error SQLSTATEs and texts.
- **Driver parameters are bound as typed constants**, not spliced into SQL text; named `?x`/`$x`
  and `IN ?` are supported. The plan cache is shared by every database of a schema template.
- **The Cascades planner plans about 2x faster** with the same plans, and removes duplicate
  expressions from its memo.
- **New documentation:** [STATUS.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/STATUS.md) is the readiness statement;
  [compatibility](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/compatibility.md) and [upgrading](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/upgrade.md) pages cover sharing data with Java and
  moving between versions.

**Required versions:** Java `fdb-record-layer-core` 4.14.2.0, FDB C++ client 7.3.77 (7.3 wire
protocol), Go 1.26.x.
