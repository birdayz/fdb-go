fdb-go v0.2.0 is the first release since v0.1.0. It moves the Java target to Record Layer
4.14.2.0 and changes SQL storage, so read **Upgrading from v0.1.0** before pointing it at existing
data. The full list is the `v0.2.0` entry in the changelog linked below.

**Upgrading from v0.1.0**

- **SQL storage changed; nothing migrates automatically.** The relational key space is Java's
  `RelationalKeyspaceProvider` layout byte for byte, so Go and Java open each other's databases and
  schemas, but SQL data written by v0.1.0 is not readable. Recreate it, or export and re-import it
  as described in [docs/upgrade.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/upgrade.md).
  For record stores used directly through the record layer, check the format-version rules in
  the same guide before opening v0.1.0 data.
- A database path is `/DOMAIN/DATABASE`, as in Java. Register the domain once per process before
  use: `sqldriver.RegisterDomainIfNotExists("FRL")`.
- **Restart paged queries.** Do not resume a continuation minted by v0.1.0: many plans changed. A
  stale continuation is refused when the new plan's outermost cursor is an index or ranged scan,
  but, as in Java, it is not detected for an unfiltered primary scan or an in-join reading an
  in-union.
- `FDBDatabase.Run` and its variants retry the way Java's transaction runner does: at most 10
  attempts by default (`FDBDatabase.SetMaxAttempts`). A body that commits the context it was handed
  is refused.
- Record layer: a planned in-union takes its maximum from `PlannerConfiguration.AttemptFailedInJoinAsUnionMaxSize`,
  whose default is Java's 0, so it fails with "too many IN values" unless the caller raises it.
- SQL and driver changes that can break callers: an unknown DSN parameter is an error (22023); `#`
  no longer starts a comment; `PLAN` and `DEEP` are reserved words; a bound `time.Time` is a
  TIMESTAMP, and DATE and TIMESTAMP result columns scan as `string`.
- Go API packages moved to follow Java's: `pkg/recordlayer/indexpredicate`,
  `pkg/recordlayer/query/plan/plans`, `pkg/async/rtree`. `keyspace.FDBResolver` is removed.
- `frl` is a package of the root module. `go install fdb.dev/cmd/frl@latest` installs this release;
  the old nested module `fdb.dev/cmd/frl` is retracted. If your `go.mod` requires that module (for
  example through `go get -tool`), run `go get fdb.dev/cmd/frl@none` and then
  `go get -tool fdb.dev/cmd/frl@v0.2.0`; otherwise the build reports an ambiguous import.

**What changed**

- **Java Record Layer 4.14.2.0** is the target for wire format and SQL behaviour. Records Java writes
  through `TransformedRecordSerializer` (compressed, encrypted) are read and written, and HNSW graphs
  are written byte for byte as Java writes them for the same inserts and deletes. The remaining
  exceptions are listed in
  [docs/compatibility.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/compatibility.md).
- **SQL follows Java 4.14.2.0 where both engines run a query**: EXISTS in boolean expressions,
  recursive CTE typing and naming, case-sensitive identifiers, `LIKE`, comments,
  `COALESCE`/`GREATEST`/`LEAST`, QUALIFY with aggregates, `UPDATE`/`DELETE … RETURNING`, error
  SQLSTATEs and texts. Known differences are in
  [DIVERGENCES.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/DIVERGENCES.md).
- **Driver parameters are bound as typed constants**, not spliced into SQL text; named `?x`/`$x`
  and `IN ?` are supported. The plan cache is shared by every database of a schema template.
- **Planning is about 2x faster** (a 150,000-task planning run: 41 s to 17 s), and the planner
  removes duplicate expressions from its memo.
- **FDB client option semantics** are unchanged since v0.1.0 (`pkg/fdbgo/fdb/OPTIONS.md`).
- **New documentation:** [STATUS.md](https://github.com/birdayz/fdb-go/blob/v0.2.0/STATUS.md) is
  the readiness statement; the
  [compatibility](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/compatibility.md) and
  [upgrading](https://github.com/birdayz/fdb-go/blob/v0.2.0/docs/upgrade.md) pages cover sharing
  data with Java and moving between versions.

**Required versions:** Java `fdb-record-layer-core` 4.14.2.0, FDB C++ client 7.3.77 (7.3 wire
protocol), Go 1.26.x.
