## P2-2 — "An n<k candidate is simply INVALID" is false for the target, and v8 now depends on it (design:863, 870-872, 969-970)

- **Consequences for v8:**

  - Under the KMeans knobs, `consumerOutcome` would have to run the full reference cleanup before predicting a refusal, because Java's n<k throw comes before the knob check.
