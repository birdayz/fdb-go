## P2-1 — The terminal reconcile reuses the insert back-pressure error type (design 197-206, 413-417, 756-760, 962-967)

- **What Java does with that type:**
  - Java raises `ClusterCapacityExceededException` only at the insert cap (`Insert.java:335`).
  - The record layer converts any such exception coming out of `guardiann.insert` (including the insert's inline task) into `VectorIndexClusterTooLargeException`. The message tells the caller to run a background merge (`GuardiannVectorIndexEngine.java:142-143, 152-164`).
  - Where Go's reconcile fails, the target throws `NoSuchElementException` (`SplitMergeTask.java:397`), and it passes through unconverted.
- **What goes wrong in Go:**
  - An inline insert whose head task fails in the reconcile would surface as that back-pressure signal. Its prescribed remedy, a merge, is exactly the operation that fails.
  - Inline deletes and merges would raise a capacity type that Java never raises there.
  - The design tells the two failures apart only by where they are raised (756-760), and it poisons the same type in one place (197-199) but not the other (204-206).
  - Anything that classifies with `errors.As` cannot tell them apart. That includes the build-range capacity branch, the hand-off trigger, and a user's back-pressure loop.
- **Needed:**
  - Give the reconcile failure its own Go-only error type, carrying index, prefix, cluster, count and limit. It must never match the capacity type and never be converted to the too-large error.
  - State how each retry owner classifies it.
  - Add fixtures for an inline insert, an inline delete and a merge that hit it.

## P3

1. **The reconcile's reachability and read bound are false (design 971-983).**
   - The hard cap exists only at `Insert.java:335`. Split re-homing into neighbours (`SplitMergeTask.java:621-651`), merges and reassigns add primaries without checking it.
   - So deferred mode also reaches a reconciled count above hardMax. "Exceeds hardMax only by inserts routed … no reconcile reads more" does not hold.
   - The outcome is still parity (the target throws at :397). Restate the claim, and add a deferred fixture: a merge pushes a neighbour over hardMax, and the neighbour then cannot be split.
2. **`consumerOutcome` does not cover everything the design says it does (290-312).**
   - Go's corrective paths skip KMeans for n<k candidates (870-873) and for empty merge cores (1029-1049). `KMeans.fit` checks the size before the knobs (`KMeans.java:136-138`). So whether Go refuses under the KMeans knobs depends on the cleaned population. Either the shared function must read the cleaned population (posting plus per-PK metadata), or the design must say the skip is conservative there.
   - A bounce with at most one outstanding dependency writes follow-up tasks (`BounceTask.java:147-150, 199-200, 309`). That write constructs the quantizer, and the bounce's outcome leaves it out.
   - The population sentence (309-312) leaves out the quantizer consumer. Under trained bits 9 (the `bits9Live` row), Go skips the head task while the target's inline delete fails. Declare this under (d).
   - No (d) fixture is named. Needed:
     - a bounce whose dependency is a live collapse under collapseConcurrency 0;
     - a bounce whose dependency is obsolete;
     - a `bits9Live` task at the head;
     - a snapshot-isolation fixture where a concurrent drain commits the head task and the skipping delete still commits.
3. **The heartbeat-admin divergence is broader than stated** (the new final entry in `DIVERGENCES.md`; `indexing_heartbeat_admin.go:100-111`). "Agree whenever no stale heartbeat exists" is false in two cases:
   - **Invalid-only heartbeat:** Java reports ongoing (its parsed time is 0), Go does not.
   - **Heartbeat dated more than the lease in the future:** Java reports not ongoing, Go reports ongoing. Admission treats a heartbeat more than a day in the future as bad data (`IndexingHeartbeat.java:107`).
   - The Go test covers only a heartbeat 5 s in the future. Consider using admission's own predicate (−1 day < age < lease), and pin both cases in the JVM spec.
4. **Nits:**
   - "At least halves M per round" (893-894, and the Go test comment) is false for the measured rounds (1000→600, 15→9). Present the bound as empirical.
   - Line 913 is a leftover fragment: "child holds no member of M."
