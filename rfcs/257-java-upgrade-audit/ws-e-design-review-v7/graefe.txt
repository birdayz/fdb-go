## HIGH

**H1. Deciding in PLANNING is not the same as the target deciding in REWRITING (§5.4(c) "WHO DECIDES", ~1770-1795).**
- **What the target does:** it prunes the unfolded member in REWRITING on conjunct count, before any access path exists.
- **What Go does:** both members reach PLANNING, where `planningCostModelCompareWith` ranks max data-access cardinality first (planning_cost_model.go ~198-221), then residual count (~223), then access-path rungs. Only after those come `EstimateCost` and the hash.
- **The measured population cannot show the difference:** every prototype query scans T in full (wse8-proto-test.go:34-47), so both members always have the same access path.
- **Counterexample (SOURCE):** `id = 1 AND COALESCE(1 / 0, 5) IS NULL`.
  - Target: `[false]` wins on count, so no rows.
  - Go: the unfolded member is a primary-key probe with known max cardinality 1. It beats `PredicatesFilter(Scan(T), [FALSE])` at the cardinality rung (the filter's cardinality is its child's, plan_properties.go:668-673), and Go raises 22012.
  - An indexed `n > 0` beside an annulling fold reaches the same result through the access-path rungs.
- **The design also names the wrong rung.** It says `FilterCost`/`EstimateCost` then the hash decide. For the measured deterministic rows the residual-count rung decides. The pins must name the real rung.
- **Fix:**
  - Make the target's REWRITING decision for the groups the ported rule rewrites before they cross into PLANNING, for example a scoped `RewritingCostModelLess` prune of predicate-simplification alternatives at the boundary. RFC-186's universal-prune objection does not apply to members that differ only in their predicates.
  - Or give measured proof that no access path can separate the members.
  - Add oracle rows plus Go tests for primary-key and secondary-index conjuncts beside an annulling fold, and beside a tie fold.

## MEDIUM

**M1. The temporal lane is not closed under the ported rules or NULL (§4.3(2), ~912-935). (SOURCE)**
- **Complements break on non-canonical text.**
  - The mappings are `D > c → D >= floor(c)+1d` and `D <= c → D <= floor(c)`. On canonical text these are complements; on a DATE column holding `'2024-01-01 10:00:00'`, with c at 05:00, both are FALSE.
  - The ported NOT-over-comparison rule turns `NOT (D > c)` into the sargable `D <= c` in the same memo group, so the residual keeps the row and the index drops it. That is exactly the plan dependence the design says is removed "on EVERY stored text".
  - Fix: use half-open bounds that are exact text complements: `D <= c ⇔ D < floor(c)+1d`, `D >= c ⇔ D >= ceil(c)`, `D < c ⇔ D < ceil(c)`.
- **`<>` is missing.** State `<>`/`!=`: `<> FormatDate(c)` at midnight, TRUE for a non-NULL D otherwise.
- **NULL in the constant arms.**
  - "FALSE" for a non-midnight `=` and a saturated "TRUE (the full range)" must stay NULL-strict: under NOT, a NULL-D row is otherwise kept.
  - A literal full index range also returns NULL entries the residual rejects.
  - Test a NULL D row under each operator and under NOT.
- **IN and the explode must share one lane.** A per-row IN and its exploded `D = QOV(e)` are members of one group, so the explode's equality must inherit the IN's lane rather than re-derive it from the element type.
  - As written, a homogeneous TIMESTAMP list compared per row is unspecified.
  - A "mixed list" is textual per row but takes the lane through the IN-join. That is plan-dependent.
- **Column-to-column contradiction.** "Lane from static types" contradicts "join equality stays textual". State which constructor admits the lane.
