## HIGH

**H1. When a fold removes a sargable conjunct, PLANNING does not reach the decision the target's REWRITING makes (§5.4(c) "who decides").**
- **Rung order.** PLANNING ranks by max data-access cardinality (planning_cost_model.go:193-219) before it counts residual predicates (:221-225). EstimateCost, where FilterCost sits, comes later still (:397-410). So FilterCost is not what decides the conjunct-count rows, as the design says; the residual count does.
- **What the rung sees.** A PredicatesFilter takes its child's max (cardinality_bounds.go:131-136). A full-key primary scan proves max 1; a full scan is unknown (:167-181).
- **Counterexample (SOURCE):** `SELECT id FROM T WHERE id = 5 AND 1/0 = 1 AND 1 = 2`, where `id` is T's primary key.
  - The folded member, `[FALSE]` over `Scan(T)`, loses on the cardinality rung to the unfolded `Scan(T,[=])` with its residual `[1/0=1, 1=2]`. Go raises 22012.
  - The target prunes the unfolded select in REWRITING, before data access, and returns no rows.
- **Why the measurement missed it:** every prototype row uses the unindexed `n` (wse8-proto-run.txt:5-10).
- **Which phase decides is not fixed.** unified_tasks.go:187-199 calls the REWRITING prune "TIMING-DEPENDENT": finals promoted in a group's last round cross into PLANNING unpruned. So "Go does not prune child groups in REWRITING" is a simplification.
- **Fix:**
  - Decide filter-group folds before data access, or show a rung that makes `[FALSE]` win.
  - Measure with a primary-key or unique-index conjunct, and with an `id IN (1,2)` variant.

  - The guard (rule_partition_binary_select.go:90-106) names the `region IN (...) GROUP BY` case (plan_shape_conformance_test.go:9414).

  - The explode prototype ran plan dumps only, no rows. `in_with_join.yaml#2` (IN plus GROUP BY) changed shape unchecked (A2.diff:62-81).
- **M2. The IN-union conversion is incomplete.**
  - rule_implement_in_union.go:217-235 still extracts the sources at planning with `Evaluate(nil)`. `executeInUnion` iterates only those (executor_new_plans.go:1845-1890). This contradicts §4.1(c)'s "evaluated at open", and neither site is named.
  - The constant fork emits `ConstantValue{list, TypeUnknown}` (expr.go:1790-1793). The design never says which Java arm that takes: the deduplicated value arm or the non-deduplicated list arm (InComparisonToExplodeRule.java:162-178).
  - The prototype deduplicates at planning (`distinctInListValues`), which the design deletes. Under the new semi-join shapes (A2.diff:19, 65), a duplicate list item duplicates rows.
- **M3. The whole-suite accounting covers a stand-in, not the port.**
  - **Golden:** "16800 line(s) differ" (explaindiff log:210), neither counted nor Java-verified. The explode change, by contrast, gets 29 named plan changes.

  - **rejectsNull:** Graefe's v6 M1 corpus dump is still deferred (text unchanged).
- **M4. The temporal lane (§4.3(2)) is underspecified.**
  - **NULL:** "FALSE otherwise" and "TRUE (full range)" drop three-valued logic for a NULL D, which breaks under NOT and in projections. A full-range scan must also exclude NULL entries.
  - **Unparseable comparand:** a column comparand whose stored text does not parse has no failure arm. The design itself says old rows hold such text.
  - **Error code:** the CAST parser raises InvalidCastError, 22F3H (values.go:4534-4560), while the write path is to raise 22007. State the mapping.
- **M5. The census tests are underspecified.**
  - The time.Time census (line 942) tests a property that cannot be checked as stated.
  - "EVERY PLACE GO EVALUATES A CONSTANT" covers `EvaluateConstant` callers only. It misses simplifier_value.go:136 and :277, rule_implement_in_union.go:228 and comparisons.go:382.
  - State how each census gets its population under Bazel, and give each a positive control.
