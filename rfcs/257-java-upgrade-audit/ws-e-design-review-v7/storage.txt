## HIGH

**H1. Negation rewrites break the DATE–TIMESTAMP comparison rule (design lines 923-929).** Section 5.4 ports `NotOverComparisonRule` (Java NotOverComparisonRule.java:71-79; Go `NotComparisonRewriteRule`, rule_simplify.go:474-491, with `Negate` at comparisons.go:156-170). Section 5.4(c) says both filter members reach PLANNING. So the rule's mapping must give the same answer as its own negation on every stored text. It does not:
- **`<>` is missing.** The rule covers "five operators" (:947). `NOT (D = c)` rewrites to `D <> c`, which stays a text comparison.
  - Example: `D = '2024-01-01'` with `c` at midnight. `NOT(D = c)` is FALSE, but the text form `D <> c` is TRUE.
  - This happens on canonical rows. Neither member can use the index, so Go's answer falls to PLANNING's hash rung.
- **`D > c` maps to `D >= floor(c) + 1 day`, which is not the text complement of `D <= floor(c)`.**
  - Example: the declared legacy row `'2024-01-01 10:00:00'` in D, with `c` = 05:00 the same day. `NOT(D <= c)` is TRUE and `D > c` is FALSE.
  - The rewritten member can use the D index and wins there; on R the two members tie on hash.
- **The constant outcomes use two-valued logic.** "FALSE" and "TRUE (the full range)" (:923, :928-931) must be UNKNOWN when D is NULL. Otherwise `NOT (D = c)` and a saturated `D < c` return NULL rows, and a "full" index range must still skip null entries.
- **Fix:**
  - Map `D > c` to `D > floor(c)`. It is equivalent on canonical text, it is the exact complement, and it can never reach year 10000.
  - Add `<>` as the complement of `=`.
  - Use SQL three-valued logic for the constant outcomes.
  - Require the mapping to hold under `Negate` and `Commute`, with a property test over arbitrary stored text that includes the `NOT` forms, run through D and R.

**H2. A per-row IN and the IN-join over the same list give different answers (lines 933-937).**
- **The mismatch:** IN-join and IN-union probes use the `=` mapping "from the explode's ELEMENT type". A per-row IN compares each element as text (`cmpAny`, comparisons.go:445-470).
- **Why both matter:** section 4.1(b) keeps the IN filter and the exploded select in the same group through PLANNING, so either can be chosen.
- **Example:** `D IN (CAST('2024-01-01 00:00:00' AS TIMESTAMP))` finds the row through the IN-join on D and finds nothing through the residual on R.
- **Mixed lists too:** the per-row IN over a mixed list, which the design explicitly leaves as text, is exploded as TIMESTAMP (the DATE→TIMESTAMP edge at type.go:1410). So its explode takes the new rule while its per-row form does not.
- **Join equality:** the exclusion of join equality names no rule that separates `D = o.ts` from `D = c`. Static types alone, which is the stated rule, cannot, and the separation would have to survive the rewrite from join to correlated probe.
- **Fix:** a per-row IN uses the same per-element mapping as the IN-join, or neither does. State the join criterion, and test D and R with a midnight list and with a mixed list.

## MEDIUM

**M1. The runtime half of the "ONE assignment function" is not specified (lines 902-909, 982).**
- **The existing coercer works against the new writes:**
  - `promotionNode.coerce` (promote_prepared.go:379-391) sends every non-ENUM STRING target to `uuid.Parse`. The design swaps in `ParseJavaUUID` there but does not restrict that branch to UUID targets, so the new STRING→DATE/TIMESTAMP writes would be parsed as UUIDs.
  - DATE→TIMESTAMP, an existing edge, falls through to "invalid carrier" today.
  - TIMESTAMP→DATE does not exist yet.
- **Existing stored text has no rule:** "FormatDate of its instant" for a DATE or TIMESTAMP source holding non-canonical text needs a named parser and a failure outcome. Old-channel rows and Java-written rows are such sources, and the value layer's own layouts also accept date-only and RFC 3339 text (values.go:2733). The `SET d = d` repair and INSERT … SELECT copies depend on this.
- **The comparison needs the same parser:** it applies to a TIMESTAMP column or correlated comparand `c` before floor/ceil, with one failure outcome shared by the index and the residual.
- **Promoted values:** a promoted DATE (from a mixed list, CASE or COALESCE) must yield canonical midnight timestamp text, or TIMESTAMP-typed values will carry date-only text.

**M2. Deleting the partition guard was measured on plans only (line 593; findings.txt:7-13).**
- The guard at rule_partition_binary_select.go:89-105 exists for a 0-row execution bug.
- The prototype produced plan dumps and printed one correlation for one shape (`id IN (100, 200, 300)`). It never ran TestFDB_GroupByWithWherePush or the IN-with-GROUP-BY cases.
- So "stale" is a SOURCE hypothesis. Run those reproducers on the prototype before deleting the guard.
