## Findings, most severe first

**1. Medium (source): the vector maintainer has no unchanged-entry skip, so Go still refuses saves Java serves and still rewires the graph Java leaves alone.**
- **Java:** `VectorIndexMaintainer extends StandardIndexMaintainer` (VectorIndexMaintainer.java:100) and does not override `update`. `StandardIndexMaintainer.update` removes the entries old and new have in common (StandardIndexMaintainer.java:215-228; `skipUpdateForUnchangedKeys` is true at :209). `IndexEntry.equals` compares key and value (IndexEntry.java:268-270). So a save that changes only fields outside the vector makes no HNSW call.
- **Go:** `vectorIndexMaintainer.Update` (`vector_index_maintainer.go:203-223`) deletes every old entry and inserts every new one. `removeCommonEntries` exists (`index_maintainer.go:328-335`) but is used only by the standard maintainer. My grep found no skip in the vector maintainer; the control hits in `index_maintainer.go` show the search itself works.
- **Effect (a):** with 9 to 15 extra bits, after the centroid is set, such a save reaches `Delete` of a present node, and `raBitQuantizerAdmits` (`hnsw.go:888`) refuses it. Java serves it. So these claims are wider than Java:
  - DIVERGENCES.md:2131-2134, "refuses every save";
  - CHANGELOG.md:491-495, "refuses saves";
  - 7.17 :2746-2762.

  The JVM spec only saves new records, so it cannot see this.
- **Effect (b):** for every VECTOR index at any bit count, such a save deletes and re-inserts the node. That rewires its edges, can move the entry point, and samples the statistics again. This is the same write-side divergence 7.17 :2764-2768 says is fixed ("Go rewired the graph Java leaves untouched"). This half predates revision 17, but it sits under the claim revision 17 makes.
- **Fix:**
  - drop common entries in `vectorIndexMaintainer.Update` as Java does;
  - add a JVM row to `hnswExtraBitsProbe`: after the centroid, re-save record 1 with only a non-vector field changed;
  - add a unit pin that the graph bytes are unchanged after that save.
