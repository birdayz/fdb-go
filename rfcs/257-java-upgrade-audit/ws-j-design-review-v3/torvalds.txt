   - evidence-v3 hashes only 10 files. Not hashed: `metadata_evolution_validator.go`, `fdb_store_catalog.go`, `key_expression.go`, `index_predicate.go`, `metadata.go`, `metadata_validate_records.go`, `errors.go`, and every new test.

   - The widening mutations the design claims (:408), and the F13 JVM run, exist only as `/var/tmp` logs. Those logs do not record the mutation text or a presence count.
   - `just test` executed only 45 of 94 targets (49 were cached), on a tree that differed in `pkg/simfdb`.
   - Fix: hash every landed file and test, and commit the mutation evidence.
2. **The ratchet pins classes, not content.**
   - Content is pinned for only 165 runs (161 equal + 4 companion).
   - The 180 metadata-diverge runs already differ in `records`. A new descriptor regression in any of them, such as a changed column type or nullability, leaves the class unchanged.
   - The 121 reject runs do not pin Go's SQLSTATE.
   - The oracle catches an F12 regression only by chance: in mutation M-c3, only 3 runs moved.
   - The "deterministic bytes" claim (§0 :106-108) rests on just two passes.
   - Fix: pin a Go canonical digest (or Go's rejection code) for each run next to its class, and assert in-process that two Go builds of each body produce identical bytes.
3. **F13 breaks existing stores without a migration path.**
   - After this change, v0.1.0-persisted metadata no longer loads if its union is named `UnionDescriptor` without a usage option, or if it has any unsigned field. The stores that use it stop opening.
   - CHANGELOG lists this under "Changed", but the Compatibility block and any migration steps are missing. Index entries at or above 2³¹ for uint32 fields were written unsigned, so they need a rebuild once the field is retyped.
   - `SetRecordsWithUnionName` (metadata.go:271) skips `fetchUnionDescriptor`. It therefore builds metadata that this same binary refuses when reloading it (metadata_store.go:79, fdb_template_catalog.go:280).
   - Fix: refuse any union name that differs from what `fetchUnionDescriptor` finds.
4. **The widening claims go beyond what the test pins.**
   - `TestFDB_SchemaRebindAcceptsLiteralCarrierWidening` (fdb_catalog_test.go:848) hand-builds protos and never opens a store.
   - "The index keeps its versions" holds by construction, and "the store has nothing to rebuild" (design :404-407) is a SOURCE claim.
   - The path users actually take — rebuild from DDL, then `RepairSchema` — is not exercised.
   - CHANGELOG says rebinding "is accepted", but that holds only when literal carriers are the sole difference. A template that also holds an F1-affected root is refused ("key expression changed") until §4 lands. That refusal is correct and fails closed, but it should be stated.
   - `frl meta evolve-check` (meta.go:117-121) has no widening option, so it refuses the exact pair the catalog admits. That contradicts fdb_store_catalog.go:280, which calls it "the same guard".
