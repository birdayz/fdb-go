   - Every relational template seeds its metadata version from the template version (`builder.go:487`, default 1 at `:112`). `addIndexCommon` then bumps the version once per index (`metadata.go:586-588`). No relational path sets index versions: 0 hits in `core/{metadata,fleet,ddl}` and `embedded/ddl.go` (control: 6 hits for `SetVersion|AddIndex` in `builder.go`).
   - So a v2 rebuilt from the same DDL moves every index's added version up by one. `RepairSchema` then refuses at `metadata_evolution_validator.go:511`, before the root comparison at `:563-568`, which is where the widening arm lives.
   - `TestFDB_SchemaRebindAcceptsLiteralCarrierWidening` builds the index proto by hand with versions 1/1 and the same metadata version in v1, v2 and v3. It never opens a store, so it cannot see this. The existing gate test starts v1 with no index (`evolSetup`).

   - Needed: pin it through a DDL-built v2 via `fleet.SaveTemplate` + `RepairSchema`, with rows written before and read after. Otherwise mark the path as gated on §4 everywhere it is claimed.

2. **Landing F1 opens the drop-and-recreate hazard, but its guard is scheduled for step 2 (SOURCE).**
   - `DROP SCHEMA TEMPLATE` followed by `CREATE` gives version 1 again with the same metadata version. The store's version check therefore does nothing.
   - Every schema still bound to t@1 then reads its old truncated `nested_then_top` entries under the corrected root. The target serves reads from those entries, and Go's own maintenance leaves the old entries orphaned.
   - `validateSchemaRebind` also returns nil when the bound version is gone (`fdb_store_catalog.go:311`), so the rebind is not validated either.
   - §2 (:262-264) itself names F1 as a cause, yet §8 justifies the timing with "the new numbering". Land the guard and Java's gone-version refusal with 3.1, before merge.

3. **The carry rule's "EQUIVALENT definition" (§4 :681-682) is wrong in both readings.**
   - Neither validator compares index predicates: 0 lines in Java `MetaDataEvolutionValidator.java` or in Go's validator (controls: 13 and 9 lines of `LastModifiedVersion`).
   - Reading 1, root-only equivalence: a changed `WHERE` keeps the index's versions, and the sparse index silently goes stale.
   - Reading 2, whole-proto equivalence: every multi-option index stored before F12 (different order only) counts as changed. It would then be rebuilt, or left DISABLED above 200 records.
   - Needed: define equivalence as type, record types, root (up to the carrier), predicate, the option map (order-insensitive, minus ignored options) and PK positions. Add FDB cases for a predicate-only change and an order-only change.
