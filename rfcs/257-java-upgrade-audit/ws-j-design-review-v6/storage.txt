## HIGH
**1. In-code builds of a shape-(d) file switch unions silently** (landed, found by reading source).
- **Before the upgrade:** `SetRecords(fd)` took the message named `UnionDescriptor` unconditionally (`e48f5b496:metadata.go:276-277`, `:330`), so records were framed by its field numbers.
- **Now:** `SetRecords` (`metadata.go:284` → `setRecords`, `:336`) takes the usage=UNION message or the one named `RecordTypeUnion`. `AmbiguousLegacyUnionError` exists only in `RecordMetaDataFromProto` (`metadata_proto.go:376`).
- **Consequence:** a library user who builds metadata from a compiled descriptor holding both messages now reads existing rows under the other union's field numbers. The design's own reason for the refusal ("refusing is the only answer that cannot misread them") applies here unchanged. §4c scopes only stored metadata, and the CHANGELOG does not warn about this case.
- **Fix:**
  - Run the (d) check at the end of `Build()`, which covers both paths and still comes after the target's checks.
  - Exempt an explicitly named union.
  - Pin it with a unit test and a mutation.

## MEDIUM
**2. The (d) exemption is broader than the SQL shapes need, and it opens a misread with no way out.**
- `messageUsedAsFieldType` (`:436`) exempts `UnionDescriptor` when it is the type of a field in *any* message.
- SQL DDL emits only the messages reachable from each table (`builder.go:749-756`), so a table or STRUCT named `UnionDescriptor` is always reachable from the union.
- The unit case "UnionDescriptor as a nested field's type" (`metadata_validate_records_test.go:401`) pins a `Holder` that is *not* reachable from the union. That is a shape SQL cannot produce, and it is exactly the shape of an envelope message wrapping a legacy union.
- Such a file loads under the target's union, and the migration then refuses it as "nothing to migrate" (design `:1400`).
- Design `:1335` ("A legacy union is never a field's type") is an assertion, not a measurement.
- **Fix:**
  - Exempt only messages reachable from the found union through message-typed fields.
  - Flip the `Holder` case to refused.
  - Make the migration's target-choice arm handle a referenced `UnionDescriptor`.

**3. Section 4 promises byte-for-byte re-emission of EQUIVALENT indexes, but no write path can do it.**
- `CreateTemplate` → `serializeTemplate` (`fdb_template_catalog.go:250`) marshals `ToProto()`, and `indexToProto` (`metadata_proto.go:533`) builds a fresh `gen.Index`. Nothing carries a per-index raw proto.
- "Byte for byte, unknown fields and extensions included" (design `:1024-1027`) therefore has no carrier.
- **Fix:** name the carrier (for example, a source proto on `Index`, re-emitted for EQUIVALENT indexes and dropped on any setter), or narrow the claim.

**4. The single-write-path claim (`:602-612`) contradicts writes the design itself requires.**
- **`RestoreTemplateVersion`:** it must bypass the guard. If it runs the no-lane check, restoring a pre-F2 tenant's saved bytes (a `long_value` bitmap key) is refused. That blocks the only way out for exactly those tenants.
- **Other writes outside `CreateTemplate`:**
  - the F11 migration's byte-for-byte copy, which `serializeTemplate` cannot perform;
  - the oracle fixture's raw write;
  - a second `CreateTemplate` implementation (`template_catalog.go:87`).
- **Fix:** enumerate every write path and state which checks each one runs (guard, lane check, header check).

**5. The fresh-name guard is keyed per version, but the text says per name.**
- §4 (`:988-989`) and §9(j) say a *name* with dangling bindings is refused. The guard (§2) is keyed on (name, version).
- So `CREATE SCHEMA TEMPLATE t` at v1 is admitted while schemas bind (t, 3).
- A later `Restore(t, 3)` then puts two numbering histories under one name. That breaks the premise at `:1086-1088` that every stored version agrees with the latest. It fails closed, but it strands the new schemas at rebind.
- **Fix:** make the fresh-name check cover the whole name, or have Restore refuse when versions of t were stored after the drop.
