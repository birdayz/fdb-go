## MEDIUM

**1. The landed (d) exemption covers more files than the ones it was meant for** (metadata_proto.go:424, :436).
- The exemption applies when `UnionDescriptor` is the type of any field anywhere in the file. That includes fields of messages the found union never reaches, and fields of the legacy message itself.
- The SQL shapes it is meant to admit are exactly the messages reachable from the found union: a table is a union field, and a STRUCT is reachable from a table. `FileDescriptorSerializer.java:118-139` emits only reachable types.
- **The gap:** in a hand-written (d1) file, a legacy `UnionDescriptor` union that an envelope references (`message Batch { repeated UnionDescriptor records = 1; }`) now loads silently under the other union. That is a misread, the one outcome the refusal exists to prevent.
- The design's ":1335 A legacy union is never a field's type" is an unmeasured absolute. No Java test proto uses a union message as a field type (control: `MySimpleRecord` in 3 files), but that shows the shape is rare, not that it cannot occur.
- **Fix:**
  - Exempt only messages reachable from the found union.
  - Pin the envelope shape as refused, in a unit test and the JVM spec.
  - Scope the sentence.
  - Declare that migrating toward the target's union is refused for this shape, because removing the message leaves a dangling reference.

**2. The EQUIVALENT class contradicts itself and has no way to write its output** (section 8 step 3).
- **The comparison (:1004)** covers `index_type`, `value_expression`, unknown fields and extensions. A DDL rebuild never carries any of them. So the test at :1029, which expects EQUIVALENT for such an index, cannot pass: the index becomes CHANGED and loses those fields.
- **Java normalizes them:** `index_type` becomes the type plus its options, and the stored option list is ignored (Index.java:198-204). `value_expression` is folded into the root (:215-218).
- **Nothing emits the stored proto:** the save path is `CreateTemplate` → `serializeTemplate` → `ToProto` → `indexToProto` (fdb_template_catalog.go:151, :250-252; metadata_proto.go:533), which builds a fresh `gen.Index`. So "re-emitted verbatim, byte for byte" (:1026) has no mechanism, and an unmarshal followed by a marshal is not byte-stable anyway.
- **Fix:**
  - Compare the known fields as Java normalizes them.
  - Leave unknown fields and extensions out of the comparison.
  - Add an Index-level raw carrier that `indexToProto` emits for EQUIVALENT indexes.
  - Claim proto equality, unless raw sub-message bytes are spliced in.
  - Declare what WIDENED and CHANGED drop.

**3. "Every template WRITE goes through one chokepoint" (:603) collides with the unit's own verbatim writers.**
- `RestoreTemplateVersion` (step 1) must store the backup's exact bytes, which `CreateTemplate` cannot do, because it re-serializes. So the restore bypasses the chokepoint, and the sentence is false.
- If the restore did go through `CreateTemplate`, the tenants that most need it would be refused: a pre-F2 bitmap version with no lane.
- Test 5's v1 (:1128-1129, a pre-port bitmap template) would be refused by the check that lands in its own step. So would the F11 byte copy.
- `CreateTemplate` has two implementations (fdb_template_catalog.go:127, template_catalog.go:87).
- **Fix:** put the check on the build path, name the exempt raw-write routes, and store test 5's fixture and the oracle's through the raw route.

**4. The restore's header check refuses correct restores** (:386).
- `RepairSchema` rewrites only the schema row and never opens the store (fdb_store_catalog.go:482-491).
- So a tenant rebound to (t, v) and not opened since holds an older header version, and requiring equality refuses its only way out.
- A correct metadata version legitimately sits above a header. The real contradiction is a header above the metadata version.
- **Fix:** refuse only when a header's version is greater than the metadata version. State how many bound stores one transaction can check. Correct DIVERGENCES:2819 to match.
