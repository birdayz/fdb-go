## MEDIUM
**M1. DIVERGENCES.md presents an owed refusal as landed (`:2929-2931`).** It says Go's `CreateTemplate` refuses re-issuing a Java-deleted version "at or below the latest, the next entry".
- `CreateTemplate` (`fdb_template_catalog.go:150-189`) refuses only an exact duplicate and reads bindings from `latest+1` (`:182`). The next DIVERGENCES entry says nothing about this.
- So today this sequence succeeds: Java `deleteTemplate(t,2)` while a schema binds (t,2), with (t,3) stored; then a library `CreateTemplate(t,2)`. It silently rebinds (t,2)'s schemas to the new metadata.
- SQL and `fleet.SaveTemplate` are protected by the save action's check.
- Say "owed by step 3", as 4e.3 does.

**M2. Fan type 7 is false on Go's parse route.** 4e and the 3.6 marker (`:1675-1677`) say both engines parse it into unknown fields. Go's parser does not:
- protobuf-go v1.36.11 decodes an optional proto2 enum with `coderEnumPtr = coderInt32Ptr` (`internal/impl/codec_unsafe.go:12`), and nothing in `internal/impl` consults `IsClosed`.
- So stored bytes arrive with `FanType=7`. `fieldFromProto` accepts it (`key_expression_proto.go:272`), and `fanTypeFromProto` reads it as SCALAR (`:24-33`).
- Java puts 7 into unknown fields, so the required `fan_type` is unset and `parseFrom` of the stored MetaData fails (`RecordLayerStoreSchemaTemplateCatalog.java:221`).
- The JVM row builds Go's input in memory with `SetUnknown` (`key_expression_absent_child_conformance_test.go:97-101`), which skips the parser. It tests a simpler cousin, not the stored-bytes route.
- **Fix:** refuse a fan type outside {1,2,3}, and pin it by `proto.Unmarshal` of bytes against the JVM's parse.
- Null interpretation 7 gives the same result in both engines (NOT_UNIQUE).

## Sound, checked against source
- **Java texts:** the duplicate and delete messages match `RecordLayerStoreSchemaTemplateCatalog.java:243/309/323`. Java's `deleteTemplate(name, version)` reads no bindings, and Java only maintains `TEMPLATES_VALUE_INDEX`, never reads it.
- **Delete versus bind:** `DeleteTemplateVersion` reads the row and a limit-1 `(t,v)` range, and the bind reads the row, so they conflict in either commit order. A refused write commits nothing.
- **Guard and listing:** both fail closed on an index that is not READABLE.
