2. **Present-tense claims for step 3's unlanded work.** On this tree, a library `CreateTemplate(t, 2)` under a Java-deleted bound (t, 2) is still admitted.
   - `DIVERGENCES.md:2929-2931` says `CreateTemplate` refuses re-issuing a version at or below the latest; that refusal is step 3's.
   - `CHANGELOG.md:360` says a new version rebuilds a changed key through "the carry rule".
3. **`CreateTemplate`'s doc comment is false now.** It says "Matches Java's createTemplate exactly … Adding validation in Go would diverge", directly above the guard that has already landed. This is the third round it has been noted; fix it now rather than in step 3.
4. **The "four shapes Java loads" entry includes a doubtful depth arm** (`DIVERGENCES.md:3252-3253`). This is from reading the source, not measured.
   - Java parses stored bytes with protobuf's default recursion limit of 100. Each key-expression level costs two message levels.
   - So Java refuses a nesting deeper than about 49 at parse time, and cannot load one past Go's cap of 128.
   - Go therefore admits depths of roughly 50 to 128 that Java refuses.
5. **The relational error surface differs from Java's** (also from reading the source).
   - `deserializeTemplate` maps a `MetaDataProtoDeserializationError` to XX000.
   - Java's `loadSchemaTemplate(name, version)` maps that `MetaDataException` to 42000 (`RecordLayerStoreSchemaTemplateCatalog.java:207-208`, `ExceptionUtil.java:72-74`).
   - `MetaDataError` does not unwrap to `RecordCoreError`. So `errors.As(…RecordCoreError)` fails for the subspace-counter case, and the Status line's "RecordCoreException hierarchy" holds only for `KeyExpressionDeserializationError`.
6. **The hooked test covers two of the pairs 3.2 lists** (`:1236-1240`).
   - `TestInMemory_VersionGuard_BindAndDeleteSerialize` hooks SaveSchema and RepairSchema against a delete.
   - A fresh `CreateTemplate` after DROP against a bind is not hooked, and 4e does not say so.
   - 4e item 4's "1.2's convention" should read 3.2.
7. **The restated step 3 in 4e names only the index classes.** It omits the carry of record-type keys and union-field numbers, which is the unit's own rationale. Name it.
