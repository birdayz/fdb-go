## HIGH

**H1. In Go, the whole-conjunction port never sees a single-table WHERE (§5.4a/c/g/h).**
- **What Go builds:** a one-source WHERE becomes `LogicalFilterExpression` (from `cascades_translator.go:3007`) under a `LogicalProjectionExpression`.
- **What the rule matches:** QueryPredicateSimplificationRule matches only `SelectExpression` (`rule_query_predicate_simplification.go:31`).
- **Nothing converts one into the other:** among the rules that match a filter, only `rule_in_to_explode.go:305` and `rule_push_filter_below_join.go:141` build a select.
- **Go's own EXPLAIN lines confirm the shape:** `Project(PredicatesFilter(Scan(T)))` (evidence-run.txt:1080, 1088, 1320).
- **Consequence:** with the 19 folds deleted, nothing simplifies these predicates. Every §5.4 row is single-table, so after the port (SOURCE):
  - Go evaluates the unfolded predicate and raises 22012 where the target answers rows (`null_strict_div0_cast_null_is_null_where`, `coalesce_true_erroring_tail_where`, `conj_true_where`);
  - the tie rows are not ties in Go, so the promised hash-rung mutation cannot redden any of them;
  - §5.4h's rungs are never reached.
- **The design handles the filter shape only for the explode rule** (lines 535-544).
- **Trap in the obvious fix:** reading the filter as a select and yielding a `SelectExpression`, as §4.1(b) does, makes every fold lose, because fewest selects wins (`RewritingCostModel.java:70-77`; `isSelectExpression`, `planning_cost_model.go:160-163`).
- **Fix:**
  - Specify how the rule reaches a one-source filter: either translate the WHERE as the target's select, or run the rule over the filter and yield the same kind of expression.
  - Cover its interplay with Go-only `FilterDropTruePredicatesRule`/`NoOpFilterRule`.
  - Measure one deterministic, one conjunction and one tie row on a fold-free tree.

**M2. The fold census misses three more translation-time folds (§5.4 "four places").**
- `expr.go:1095`, `:1185` and `:1374` call `EvaluateConstant` on any constant subtree during translation:
  - widen to DOUBLE;
  - narrow a float against an integer column, which rewrites the operator and clamps out-of-range bounds;
  - narrow to FLOAT.
- `amount > 3 - 2` is folded there. So the third case of `TestPlanHarness_ConstantExpressionComparandIsSargable` does not show sargability without folding.
- The census test only enumerates the callers of the three Simplify entry points. It must assign `EvaluateConstant` callers too.

**M3. The NOT_NULL arm turns wrong nullability typing into wrong answers (§5.3).** (SOURCE)
- The census drives NOT NULL classes only with an erroring child. The other failure is a value Go types NOT NULL that can still be NULL: IS NULL then folds to FALSE without evaluating it.
- **CAST:**
  - `CastValue.Type` says a CAST "may produce NULL on out-of-range / unsupported source" (`values.go:4234-4240`), and `castEvaluated` falls through to `return nil, nil` (`:4685`).
  - If CAST takes its operand's nullability, every such arm must raise, as Java's CastValue does, or be refused at planning.
- **Scan leaves:**
  - They type proto3 scalars, required fields and flat repeated arrays NOT NULL (`proto_field_type.go:28-31, 58-65`).
  - FieldValue inherits the root's nullability (`field_value.go:456-490`), which widens only on null-on-empty edges (`quantifier.go:393-404`) or the gated-path seeds (`ordinal_seed.go:241-249`).
- **Missing tests:**
  - `IS [NOT] NULL` over a NOT NULL column of the null-supplying side, on every Go outer-join path: materialized NLJ, null-on-empty, gated and clustered;
  - a CAST whose evaluation yields NULL.

**M4. The DATE-key projection has no stated source for the comparand's type, and its consumers are not enumerated (§4.3).** (SOURCE)
- **The analogy fails:** the float projection it cites keys on the runtime carrier. DATE and TIMESTAMP comparands are both `string` (`scan_range_binding.go:586-591`), and `coerceTupleElementForKey`'s operandType is passed nil at both call sites (`:556`, `:981`).
- **Why it matters:** projecting by the shape of the text would probe a legacy date-only TIMESTAMP value as a DATE through the index, while the residual lane compares instants. That is the plan-dependence the lane exists to remove.
- **Fix:**
  - Carry the lane, or the comparand's static type, from the plan to the binder.
  - List what is not covered first: per-row IN/NOT IN, IS DISTINCT FROM, GREATEST/LEAST, and join equality.

**M5. The explode port is missing its phase and termination rules (§4.1b).**
- **Phase:**
  - Java registers the rule in PLANNING only (`PlanningRuleSet.java:108`). Go also fires it in REWRITING (`default_rules.go:118`), where its select loses the select-count rung.
  - More generally, Go's REWRITING runs all of `DefaultExpressionRules`, while Java runs five (`RewritingRuleSet.java:50-72`). So Go's prune ranks members the target never builds, and the (j) tests should assert the member set, not only the survivor.
- **Termination:**
  - The deleted idempotency guard exists "to prevent infinite memo growth from fresh-alias SelectExpressions" (`rule_in_to_explode.go:65-68`).
  - State what replaces it, and add a test that the memo stays bounded.
- **Conjuncts:** the filter holds the whole WHERE as one predicate (`cascades_translator.go:3000-3006`). Say that reading it as a select splits the AND into conjuncts.
