## HIGH
**1. Shape (d)'s refusal rejects Java-valid SQL templates (source, not probed).**
- `refuseAmbiguousLegacyUnion` (`metadata_proto.go:415`, called at `:265`) refuses any file that has a top-level message named `UnionDescriptor` other than the union it found.
- A quoted table or struct named `"UnionDescriptor"` produces exactly that message. `ToProtoBufCompliantName` leaves the name unchanged (`protoname.go:68-87`, `builder.go:500`), and no name is reserved. It sits beside `RecordTypeUnion`, which carries the UNION usage option.
- Java's `fetchUnionDescriptor` gives that name no special meaning (RecordMetaDataBuilder.java:322-358), so the target creates and loads the template.
- Go's own DDL also builds and saves it (`builder.go:483` never calls the refusal), and then the catalog cannot load it (`fdb_template_catalog.go:280`).
- The pre-upgrade loader would have taken the table message for the union, so Go never wrote records under it. There is nothing for the refusal to protect.
- **The planned migration makes it worse.** Its default for (d) is the pre-upgrade choice (design :1249). That would move the UNION usage onto the table message and remove it from `RecordTypeUnion`, corrupting a template Java wrote. `SaveMigratedLegacyMetaData` also writes to `FDBMetaDataStore`, not the catalog.
- **False claims:** design :1219 ("framed by the OTHER message") and :1228 ("SQL DDL produces none of them"), plus the matching CHANGELOG and DIVERGENCES text.
- **Fix:**
  - Do not refuse when the legacy-named message is itself the type of one of the found union's fields.
  - Never default the migration in that case.
  - Add JVM shapes: a target-created `CREATE TABLE "UnionDescriptor"` and a `CREATE TYPE AS STRUCT "UnionDescriptor"`, each loaded through Go's catalog.
  - Correct the three population claims.

## LOW
4. **Restore has no integrity check.** `RestoreTemplateVersion` bypasses the guard and relies on documentation. If the restored metadata's version is above a bound store's header version, the next open rebuilds or clears indexes under the wrong metadata; if it is equal, rows are misread. At minimum, refuse unless the version equals the bound stores' header versions (the bound schemas can be listed from `TEMPLATES_VALUE_INDEX`).
5. **Index-level load precedence still differs.** Java checks each index's record types before `new Index`, one index at a time (RecordMetaDataBuilder.java:187-219). Go runs `indexFromProto` over all indexes first (`metadata_proto.go:273-281`). So an unknown record type combined with a repeated option gives Go's `DuplicateIndexOptionError` where Java says "Unknown record type". 4c's "then the rest" claims more than this; add a JVM shape.
6. **:504 is ambiguous.** "Coverage surface exposes the key's operand fields" can be read as letting the index cover `d`, but the entry holds `d + d`. Reword: a function-key column is never covered, and its operands come from the fetched record.
