## HIGH

**1. Shape (d) is refused on load with no working exit** (metadata_proto.go:415-431; design :1250-1252; CHANGELOG (d) remedy).
- **Why "take the usage from the other message" fails:** Java treats any message named `RecordTypeUnion` as a union candidate unless it carries UNION usage, and NESTED usage throws (RecordMetaDataBuilder.java:335-352).
  - So for the arm "UnionDescriptor beside RecordTypeUnion, migrated to the legacy choice", the migrated file is refused with "Only one union descriptor is allowed".
- **The target's-choice arm stays refused:** migrating to the target's choice "leaves the file as the target reads it". But the refusal fires on the mere presence of a message named `UnionDescriptor` that is not the union, so this loader refuses the migrated file forever. That includes Java-written files the target loads.
- **Fix:**
  - Define a marker that survives a reload and that Java reads identically, or declare these arms unmigratable.
  - Unit-pin that every migrated (d) output passes both `fetchUnionDescriptor` and `refuseAmbiguousLegacyUnion`.

## MEDIUM

**2. The load-order fix is incomplete.**
- **Index faults:** Java resolves each index's record types before `new Index(proto)`, one index at a time (RecordMetaDataBuilder.java:187-219). Go builds every index first (metadata_proto.go:273-281) and associates them afterwards (:283-310).
  - A duplicate-option or key-expression fault therefore hides an unknown record type, in the same index or in an earlier one.
- **RecordType entries:** Java throws on a RecordType entry naming an unknown type (:221-222 → :986-990). Go `continue`s (metadata_proto.go:316-318).
- **Fix:** add JVM shapes for both.
