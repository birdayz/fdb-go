1. **P1 — Correct the signature-input contract across training transitions.**  
   [Design lines 126–127](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-d-design.md:126) mandate hashing exactly the persisted vector bytes. Java instead hashes `getRawData()` of the vector supplied to the signature function. Reference loading first [applies the current storage transform](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/StorageAdapter.java:388); [StorageTransform](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/common/StorageTransform.java:61) transforms plain references written before training while preserving encoded references. [Collapse then hashes those loaded vectors](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/CollapseTask.java:489). Consequently, an old plain reference read after training can produce a different signature from the design’s retained original bytes.

   Specify signature provenance separately for untrained plain, transformed plain, and already encoded vectors. Add a retained JVM transition fixture covering collapse, reopen, replica folding, and deletion, including both-direction membership-key interoperability. The signature-rule disagreement is established by source; any resulting upstream corruption still requires the prescribed JVM evidence.

2. **P2 — Resolve engine-specific configuration validity and execution admission.**  
   [Design lines 61–64](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-d-design.md:61) generalize the extra-bit boundary. Java’s 1–15 check belongs to [HNSW and applies only when RaBitQ is enabled](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/hnsw/Config.java:104). [GuardiANN Config](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Config.java:196) has no equivalent check and also accepts configurations whose KMeans iterations/restarts or metric fail later. [KMeans validates iteration bounds](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/KMeans.java:135) and [supports only Euclidean/cosine](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/KMeans.java:652).

   Add an explicit per-engine matrix separating Java metadata validity from execution capability. Require unsupported capabilities to fail before record mutations or task removal, preserving the requested configuration and a typed error. Otherwise, faithfully porting constructor checks leaves the mutation-free promise underspecified: current Go [buffers record writes before secondary-index maintenance](/home/birdy/projects/fdb-go/pkg/recordlayer/store.go:691), and Java [clears a task before running it](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Primitives.java:1025). Acceptance should explicitly cover catching admission errors and subsequently committing the caller’s transaction.

3. **P2 — Include continuation execution identity in the scan-option contract.**  
   [Design lines 108–113](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-d-design.md:108) require tri-state plan identity and unchanged materialized continuation format, but omit the separate continuation fingerprint. Current [vectorScanRangeFingerprintSalt](/home/birdy/projects/fdb-go/pkg/recordlayer/query/executor/scan_range_execution_identity.go:502) collapses absent/false through `IsReturningVectors()` and knows only the existing search fields. Updating plan equality and serialization alone therefore leaves an independent identity boundary unresolved.

   Specify canonical option presence/value in this fingerprint, including GuardiANN’s per-query knobs. Require changed-option continuation rejection and identical-option replay without another search. This can preserve the materialized payload format.
