1. **P1 — The signature contract contradicts Java across the training transition.**  
   [Design lines 126–127](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-d-design.md:126) require signatures over exactly the stored bytes. Java instead [transforms references during decoding](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/StorageAdapter.java:395), then [hashes the supplied vector’s raw representation](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/StorageAdapter.java:578). [StorageTransform](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/common/StorageTransform.java:61) explicitly transforms plain pretraining vectors while passing encoded vectors through unchanged. Training activates this transform without rewriting every old reference.

   Consequently, persisted bytes and signature-input bytes are not universally identical. Specify original, transformed, and encoded representations separately, including collapse, expansion, deletion, and rewrite boundaries. Extend the source-hypothesis fixtures to collapse before/after training and mixed plain/encoded references, in both interoperability directions. This is a demonstrated specification/source mismatch; upstream corruption still requires runtime evidence.

2. **P1 — Queued-build backpressure has no progress-producing handoff.**  
   The design requires real queued consumption and hard-cap relief, but preserves WS-C ownership without specifying the necessary scheduling change. Current [build orchestration](/home/birdy/projects/fdb-go/pkg/recordlayer/online_indexer.go:898) finishes queue draining before executing requested merges. The [queue success hook](/home/birdy/projects/fdb-go/pkg/recordlayer/online_indexer_queue.go:186) merely accumulates merge requests. Meanwhile, the [retry iterator](/home/birdy/projects/fdb-go/pkg/recordlayer/throttled_retrying_iterator.go:85) retries errors with smaller batches.

   With deferred maintenance, a committed cluster at its hard cap can reject even a one-entry replay. The split needed to relieve it waits behind the drain that cannot finish. Specify a driver-owned transition: abort the failed replay, consume committed maintenance through the existing merger, then resume from the last committed queue continuation under the same session. Preserve callback validation on actual claim/drain/retry/final transactions. Require an over-cap queued-build fixture with committed backlog; a small final-batch fixture cannot establish progress. This requires no nested GuardiANN runner.

3. **P1 — Mutation-free admission lacks the maintenance capability boundary.**  
   [Design lines 41–64](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-d-design.md:41) explicitly separate quantizer availability from parser validity, but leave analogous GuardiANN restrictions unresolved. Java [configuration parsing](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/main/java/com/apple/foundationdb/record/provider/foundationdb/indexes/GuardiannVectorIndexEngine.java:294) accepts the shared metric catalog, whereas [KMeans dispatch](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/KMeans.java:652) supports only Euclidean and cosine. Squared-Euclidean or dot-product configurations can therefore survive parsing and fail when maintenance needs KMeans. Its iteration/restart checks also occur [at execution](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/KMeans.java:135).

   Specify an engine capability table and reject unsupported maintenance configurations before record/index mutations. Preserve Java parsing separately; do not silently substitute metrics. Acceptance must include otherwise parseable configurations and verify that catching admission errors cannot leave committable writes or stranded task backlogs.

4. **P2 — Deterministic ordering is unresolved before candidate-score ties.**  
   [Design lines 233–240](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-d-design.md:233) acknowledge identity-map tie variability, but Java [reference cleanup](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Primitives.java:1541) first enumerates a `HashMap`. [SplitMergeTask](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/SplitMergeTask.java:1097) preserves that sequence into KMeans. This affects seed-to-vector selection and floating-point reduction order even without equal candidate scores.

   Prohibiting Go map iteration does not define Java-equivalent traversal. Specify that traversal contract and any deliberate divergence. Retained fixtures must expose the unmodified Java KMeans input order and intermediate numerical representations. Define which resulting bytes require exact equality and which nondeterministic outcomes receive invariant-based acceptance.

The supplied-merger-transaction correction is consistent with Java. Preserve the stated SPFresh/LIRE, approved extensions, C++7.3.77, format15/default14, and separate Lucene boundaries.
