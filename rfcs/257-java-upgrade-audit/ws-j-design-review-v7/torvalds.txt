## MEDIUM

**1. Reachability does not tell a data message from a legacy union** (metadata_proto.go:424, design :1451, :8).
- **The shape that slips through.** Take `UnionDescriptor{_B=1; _A=2; _Batch=3}` with no usage option, beside `U{usage=UNION; _A=1; _B=2; _Batch=3}`, where `Batch { repeated UnionDescriptor items = 1 }`.
  - Before the upgrade, both the loader and `SetRecords` framed the records by UnionDescriptor.
  - `U` reaches UnionDescriptor through `Batch`, so the file is exempt and loads under `U`. Every B row is then read as an A row, silently.
- **The migration cannot repair it.** The file already loads, so the migration refuses it with "nothing to migrate" (:1545).
- **Where the text overclaims.**
  - The unit case "the type of a record type's field" pins only the scalar (data) variant.
  - The status line "an envelope holding legacy unions is refused" (:8) is false when the envelope is a record type.
  - (r) (:1782) does not declare this case, which Torvalds v6 #6 asked for.
- **Fix:** either sharpen the discriminator, or declare the case and give the migration a route.
  - **Sharper rule:** refuse when UnionDescriptor, read the way the pre-upgrade loader read it, frames a record type that the found union also frames. Measure this against the SQL shapes on both engines before adopting it.
  - **Or:** declare the case in (r), DIVERGENCES and the CHANGELOG, pin it, and let an explicit `union=UnionDescriptor` migrate a file that already loads.

**2. Extending the refusal to `SetRecords` is an incomplete conversion.**
- **The only remedy offered is the wrong one for Go's own data.** The pre-upgrade `SetRecords` always framed by UnionDescriptor (`e48f5b496:metadata.go:277`). Yet the only remedy the CHANGELOG offers is to name the union the target finds. For every pre-upgrade Go writer, that is the silent misread one API call away.
- **The right in-code remedy is not stated.** It is to edit the `.proto`: mark UnionDescriptor as UNION and demote the other candidate. The error text points at `MigrateLegacyRecordsFile`, which takes a stored `gen.MetaData`, not a compiled descriptor.
- **The named escape does not survive storage.** `SaveRecordMetaData` builds through `RecordMetaDataFromProto` (metadata_store.go:79), so metadata built with the named union cannot be saved, and no Go loader will read it back. This is undeclared and unpinned.
- **A doc comment now contradicts the code.** `SetRecordsWithUnionName`'s doc (metadata.go:269-276) justifies refusing any other name by exactly this load-back argument.

**3. The EQUIVALENT carrier** (:1117-1160).
- **"Every setter of `Index` clears" cannot be enforced.**
  - `Index` exposes `Type`, `RootExpression`, `Options`, the version fields and `Predicate` as public fields (index.go:166-205).
  - `addIndexCommon` itself assigns `LastModifiedVersion` directly (metadata.go:594-602).
  - Any later direct write therefore saves the stale stored proto without a word.
  - **Fix:** have `indexToProto` re-run the class comparator when it emits, and emit the stored proto only if the index still compares EQUIVALENT.
- **"So no reader sees a difference" (:1160) is false for Go.**
  - Go's `indexFromProto` never reads `value_expression`; I found 0 reads in `pkg/recordlayer` outside the unrelated Cascades values, with `GetIndexType` hits as the control.
  - It also defaults an absent `added_version` to the last-modified version, where Java uses 1 (Index.java:215-218, :227-233).
  - The comparator folds `value_expression` into the root, but Go then maintains a carried index under the bare root.
  - **Fix:** port both into step 3, with a JVM pin.

## LOW

4. **The whole-name guard (:375).**
   - **The gap:** after `Restore(t, 3)`, a new version 4 is admitted while bindings to (t, 5) still dangle, and `Restore(t, 5)` then interleaves two histories under one name.
   - **Fix:** refuse creating (t, v) while any dangling binding of t has a version ≥ v.
5. **The restore's "bound set has not grown" re-read (:429).**

   - **Fix:** add a read-conflict range over the (t, v) index range instead of reading it.
