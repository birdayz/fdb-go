## MEDIUM

**1. The reachability exemption still exempts the natural envelope** (`metadata_proto.go:424`; design `:1451`).
- A legacy `UnionDescriptor` that a record type holds (for example a `Batch` record with `repeated UnionDescriptor`) is reachable, so it is exempt. The file then loads under the target's union, which silently misreads it.
- The migration then refuses it as "nothing to migrate", so the file has no way out.
- The unit case at `:404` covers only a scalar data message.
- "Separates a DATA message from a legacy union" (design `:1451`, code comment `:408`) is false: the rule separates reached messages from unreached ones.
- **Fix:**
  - also refuse when the reached `UnionDescriptor` has a message-typed field whose type is a record type of the found union (the SQL table and STRUCT shapes have columns there);
  - measure on the JVM whether a table-typed column exists;
  - pin a `Batch` record type on both engines.
  - Otherwise declare the residual in (r) and DIVERGENCES and give the migration an arm for it.

**2. Go's loader ignores `value_expression`.**
- `git grep GetValueExpression\|\.ValueExpression` over `pkg/` and `cmd/` gives 0 hits (control: 3 in `gen/record_metadata.pb.go`). Java folds the field into `KeyWithValue` (`Index.java:215-218`).
- Go also defaults a missing `added_version` to the last-modified version (`metadata.go:600-602`), where Java uses 1 (`:227-232`).
- Section 4 (`:1094-1107`) assumes the loader erases the difference. It does not: Go misreads the index.
- EQUIVALENT then carries `value_expression` into every new version. Go maintains those versions with the bare root while Java reads a key plus value, so the entry value bytes diverge.
- **Fix:** port both rules into `indexFromProto` inside the unit, with a JVM spec that compares entries, and correct the premise at `:1100`.

**3. The whole-name guard closes only a fresh start.**
- This sequence still produces two numbering histories under one name:
  1. `Restore(t,3)`;
  2. save v4, which the guard admits because it reads only `(t,4)`;
  3. `Restore(t,5)`.
- The claim at `:375-379` does not hold for it.
- **Fix:** have the new-version guard read t's bindings at versions ≥ v′, one range read with limit 1. No stored version is ≥ v′, so any hit is a dangling binding, and this covers both prefixes. Add the FDB sequence as a test.

**4. The restore's header check fails open on the driver keyspace split** (`:415`).
- No keyspace is named for locating bound stores (`fleet.Migrate` takes a `RelationalKeyspace`), and an absent header passes.
- **Fix:**
  - resolve each store through the opener's own function;
  - refuse a bound schema that has no header (CREATE SCHEMA always creates the store).
- The re-read of the bound set in the restoring transaction (`:428`) is O(n), which contradicts "no limit". By the design's own argument the set cannot grow, so drop the re-read or bound it.

9. **The `storedProto` carrier can go stale.** `Index` fields are written directly (`Options`, `RootExpression`), which bypasses "every setter clears". Emit the carrier only after a checked equality, or keep it off `Index`.
