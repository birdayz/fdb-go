3. **Replacement lifecycle — [design:81](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-b-design.md:81).** Enumeration is separated from build eligibility; initialization covers fresh stores and reconciliation before policy invocation. Retirement requires every replacement to be exactly READABLE. Transaction-visible state, negative-decision conflicts, lock release before transitions, named checks, and unified commit sequencing address the actual lifecycle gaps.

4. **Metadata evolution — [design:132](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-b-design.md:132).** Copied option configuration and caller-supplied change sets preserve ownership. Explicitly ignoring `unique` matches Java; unrelated validation remains active. UNION-tag correspondence, descriptor-pair traversal, separate identity/serialization tags, and descriptor-correct factories cover persisted rename/swap/name-reuse behavior. The unionless extension and correct old-descriptor rewrite loop remain intact.

5. **Rank values — [design:175](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-b-design.md:175).** Dispatch validation, declared score-column extraction, absolute ranks, singleton integer/NULL values, serializable rank lookup, and cursor preservation are specified. Exact value and packed-tuple comparisons close the existing conformance blind spot; persisted bytes remain unchanged.
