## MEDIUM

**1. The edited-file route admits changes that corrupt stored data (`:1864-1880`, (p) `:2158`).**
- The only check is that the edited file frames the stored record types at the same union field numbers. The design calls that "the whole requirement".
- It is not. The normal save path, `SaveRecordMetaData`, runs the evolution validator from the old metadata to the new (`metadata_store.go:111-117`). This route skips it, because the stored side cannot load.
- An edited file that frames correctly can still:
  - change a primary key, or an explicit record-type key;
  - change an index's root, predicate, type, options or subspace key without moving its `last_modified_version`, so `GetIndexesSince` rebuilds nothing and old entries are read under the new definition;
  - drop an index without a FormerIndex, so its data is never cleared;
  - flip `split_long_records`, `store_record_versions` or the record count key;
  - retype or remove a field of a framed message. That is the design's own "holding field retyped or removed" in the record-type-holder shape, where `Batch` is a record type with stored rows.
- **Fix:**
  - Build the stored side as the pre-upgrade loader read it: `union` named, the Go-only (d) refusal suspended, and the replay already reconstructs the loop's record types.
  - Run `MetaDataEvolutionValidator` from that to the edited file, with only the union-numbering comparison replaced by the framing check.
  - Archive the old bytes at the history key, as `SaveRecordMetaData` does.
  - Tests, each refused: a root change with no version bump, a framed field retyped, a primary key changed.

**2. The restore's "nothing binds" refusal is decided outside the restoring transaction (`:491`, `:528-536`).**
- The listing is what establishes that something binds (t,v). The final transaction only re-checks that (t,v) is not stored, and adds a conflict range that covers only writes after its read version.
- **Interleaving:**
  1. The listing sees S bound to (t,3).
  2. DROP SCHEMA S commits.
  3. A fresh CREATE SCHEMA TEMPLATE t is admitted, because nothing binds t any more, and writes a new v1.
  4. The restore reads (t,3) absent and commits.
- The old v3 now sits beside the new v1: the two-history state from Torvalds v8 #2, now reached through a race.
- ":534 only shrinks the set" misses the case where it shrinks to empty.
- **Fix:**
  - Inside the restoring transaction, do a limit-1 read of the (t,v) bindings (O(1)) and refuse if it is empty. That is sound because such bindings can only shrink, so a non-empty read means no fresh t was admitted before it.
  - Add this interleaving as an FDB test.

## LOW

**3. Stored no-lane keys that cannot be widened (`:866`).**
- The pre-upgrade generator builds bit and bitmap keys with no lane check (`e48f5b496:ddl/generator.go:861-873`, `:926-940`). On this tree the driver stores 8 such shapes (WSJLANE, measured).
- ":866" covers only the pre-F2 `long_value` entry size.
- For `v & 1` over DOUBLE, after step 3:
  - a new version from DDL is refused at the clause;
  - a new version built by hand carries the index as EQUIVALENT, and `CreateTemplateFromProto`'s lane check refuses those spliced stored bytes with 42F59.
- So such a template gets no new version at all until the index is dropped.
- **Fix:** decide whether the lane check applies to stored bytes carried unchanged (the raw-write routes are exempt for this very reason), declare the outcome in (t) and CHANGELOG, and test it.

**4. The check before a carried write is too narrow (`:1330`).**
- `CreateTemplateFromProto` checks only `RecordMetaDataFromProto`. But `deserializeTemplate` also builds tables (`schema_template.go:52-93`, where `newTable` can fail).
- **Fix:** run `deserializeTemplate`'s path on the bytes in both writers. Then ":1785" and `serializeTemplate`'s comment ("Go never stores a template no Go session can load") become true by construction; today they hold only for (d).

**5. The in-memory rationale is incomplete (`:846-857`).**
- `RepairSchema` resolves the template by name (`store_catalog.go:139-150`).
- After DROP t and a fresh t v1 (the in-memory catalog has no guard), a schema bound to the old (t,1) passes the by-number gone-version check. It is then rebound across histories, and the validator compares no predicates.
- **Fix:** declare it, or compare the stored template's identity.
