## P2 — The inline-mode bound's firing window is incomplete; Go refuses writes permanently on a cluster Java re-arms (design:883-918)

**What the design claims (894-903):** an over-max cluster in the target's inline flow lacks both SPLIT_MERGE and COLLAPSE only between CollapseTask clearing COLLAPSE and its bounce re-arming SPLIT_MERGE. A refusal there "succeeds on retry once the bounce has run".

**Why that is false.** The bounce re-arm is conditional:
1. **The collapse route replaces all states:** SplitMergeTask.java:389-394 sets the states to `{COLLAPSE}` only.
2. **REASSIGN can be added while COLLAPSE is set:**
   - The split branch excludes COLLAPSE clusters (Primitives.java:1161-1163), so updates fall through at :1177.
   - The reassign tail then *adds* REASSIGN (:1222-1249; the add is cumulative per ClusterMetadata.java:189-190). Replica or underreplication thresholds are enough to trigger it, and so is a neighbour's split cause set.
3. **CollapseTask keeps REASSIGN:** it removes only COLLAPSE (CollapseTask.java:415-416).
4. **The bounce skips its re-arm** when REASSIGN is present (BounceTask.java:294-300).
5. **The ReassignTask leaves the cluster with no flags:** it runs (ReassignTask.java:206-212), writes the target with no states (:730-735), and follows up only if the cluster is undersized (:772-774).

**Result:** the cluster ends above max with no flags. In Java, only the next primary insert re-arms it (Primitives.java:1161-1165 via Insert.java:366).

**What each engine does next:**
- **Java:** the next inline insert re-arms the split, and after the collapse that split may simply succeed.
- **Go:** the bound fires at the cap position, which comes *before* that metadata update. The refused insert is exactly the one that would re-arm, so nothing ever re-arms. Every insert into the cluster is refused until deletes lower the count.
- **Scope:** this is reachable under the design's own precondition (count ≥ hardMax built up while COLLAPSE was pending).

**Claims this falsifies:**
- the one-exception enumeration;
- "succeeds on retry once the bounce has run";
- "the target is never more available than this" (915-918).

**Why a flag predicate cannot fix it:** stored flags cannot tell this state apart from the reconcile residue.

**Needed — one of:**
- Make the refusal self-healing: before refusing a flagless over-cap cluster, apply Java's re-arm and attempt that split in the same transaction, and refuse only if the attempt ends in the terminal reconcile.
- Or declare the state under (h) with a staged JVM fixture showing Java's next inline insert re-arming and succeeding, and correct the three claims. `GuardiannConformanceAccess.setStates` can stage `{REASSIGN}` on a collapsed over-cap cluster.

## P3

1. **"Refused, which also rolls back that reconcile" (910-911) is conditional.** Capacity errors do not poison (521-525). A caller that catches the error and commits therefore commits the inline task's reconcile, plus a record with no index entry. State that.
2. **The claim-race fixture's "both sessions complete" (681-684) is conditional.**
   - The winner's drain loop can hold and refresh the lease for up to 100 drain transactions (666-669), while the loser's wait is capped at 60 s (646-648).
   - When the two sessions block on different clusters in one prefix, the loser ends with the typed capacity error.
   - Add that arm to the fixture, and state the condition under which both complete.
3. **Some "measured" labels are source-only:**
   - The KMeans row says "every live split/merge" (223), but every KMeans golden ends in a lone cluster, so no live merge was measured.
   - The "throws" arms for splitMergeConcurrency and reassignConcurrency (226-227) need precomputed neighbours; only the livelock arms and the obsolete tasks were measured.
   - "An obsolete task is therefore consumed even under a trained bits-9 index, as in the target" (307-309) has no oracle row.
   - Move these to REMAINING or measure them.
4. **The isolation of the (d) head-task peek is unstated (271-275).** A skipped delete should read the queue head at snapshot isolation, so it adds no read conflict against concurrent drains. Java's inline delete conflicts there only because it removes the task.
5. **The lease-default change has only its unit pin as evidence (641-645).** The new constant, the `Build()` resolution and `checkPreparationHeartbeats` are consistent with `OnlineIndexOperationConfig.java:61` and `IndexingHeartbeat.java:107`. But no run of `//pkg/recordlayer` after the change is recorded in the tree, and this default reaches every exclusive build. Record one before the implementation gate.
