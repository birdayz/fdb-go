## MEDIUM

**1. The version guard trusts a `v′ = latest + 1` that nothing enforces (design :388-399).**
- `SaveSchemaTemplateConstantAction` refuses only `Version() <= latest` (`save_schema_template.go:33-36`). `fleet.SaveTemplate` passes the caller's version (`migrate.go:50-54`).
- **Sequence:**
  1. Bindings at (t,3) dangle.
  2. `Restore(t,1)`.
  3. Save v5, carried from v1. It is admitted, because the range from (t,5) up is empty.
  4. `Restore(t,3)`.
- That puts two histories under one name, which is v7 Graefe #2 again. Its predicate consequence follows: equal last-modified versions, no rebuild, wrong rows.
- **Fix:** read from `(t, latest+1)`, as v7 prescribed, or refuse a carried save at `v′ ≠ latest+1`. Add the skip sequence as an FDB test.

**2. The EQUIVALENT carrier has no route to storage (:1231-1240).**
- The only store API is `CreateTemplate(api.SchemaTemplate)`. Its `serializeTemplate` marshals `rl.Underlying().ToProto()` (`fdb_template_catalog.go:251-280`), which rebuilds every `gen.Index` through `indexToProto` (`metadata_proto.go:596`). Nothing is preserved at the index level.
- So a carried `gen.MetaData`, wrapped back into a template, loses its splice at the store:
  - `index_type` becomes `type` plus a `unique` option;
  - `value_expression` becomes a KeyWithValue root;
  - unknown fields and extensions are dropped.
- "Stores that same `gen.MetaData`" therefore has no mechanism behind it.
- **Fix:** specify a bytes path (store the validated `gen.MetaData` verbatim, with the (d) and lane checks run over its load), and say what the in-memory catalog does.
