## MEDIUM

**1. The EQUIVALENT carrier has no route to storage (design :1232-1238).**
- The design says the save "stores that same `gen.MetaData`". But the only template writer is:
  - `CreateTemplate(txn, api.SchemaTemplate)` → `serializeTemplate` → `md.ToProto()` (`fdb_template_catalog.go:252-275`).
  - `ToProto` rebuilds every index through `indexToProto` (`metadata_proto.go:596-635`), which drops `index_type`, `value_expression`, unknown fields and extensions. The design says this itself (:1176-1180).
  - Nothing on `Index` keeps a stored proto (grep: none).
- So the spliced Index is lost when it is stored, and the (d) check and the lane check run over `rl.Underlying()`, not over the carried bytes.
- **Fix:**
  - Name the mechanism: a bytes-carrying template, or a catalog write that takes a `gen.MetaData`, whose checks run on `RecordMetaDataFromProto` of exactly those bytes.
  - Pin the result at the catalog layer: read the `Templates` row's `META_DATA` back and compare its Index message.

**2. The lane check types exempt operands wrongly (:722-723, :759-760).**
- The design says an order-wrapped operand "takes that column's type", and it plans a test that ACCEPTS one.
- In Java, `OrderFunctionKeyExpression.toValue` is a `ToOrderedBytesValue` (`:100-101`), whose type is BYTES (`ToOrderedBytesValue.java:100-101`). CARDINALITY is INT (`CardinalityValue.java:84-86`).
- So `bitand(order_desc(a), 1)` is (BYTES, INT), which has no lane:
  - the target fails every query of the table (the stored no-lane case of section 3.5);
  - Go's own `nullableLong` refuses every write.
- **Fix:**
  - type each exempt function by its Value's result type;
  - refuse the order-wrapped case;
  - flip the planned test.
