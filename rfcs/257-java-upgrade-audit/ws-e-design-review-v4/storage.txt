## High

**H1. The index-state conflict change (lines 1241-1249) contradicts Java's SQL read path and would pin a divergence as parity.**
- `getAllIndexStates` (a conflict range over the whole index-state subspace) is not on Java's query path. Its only core caller is `vacuumReadableIndexesBuildData` (`FDBRecordStore.java:5332`).
- Java's SQL path adds index-state read conflicts in one place only:
  - Planning reads `store.getRecordStoreState()` with no conflict (`PlanContext.java:250-251`).
  - The plan-constraint check (`DatabaseObjectDependenciesPredicate.java:98`) also adds none.
  - `scanIndex` adds one conflict KEY per index it actually scans (`FDBRecordStore.java:1500` → `:4241-4242` → `:4187-4198`).
- Porting the range makes a Go reader's commit fail when an index it never touched changes state. The target does not fail there.
- Go already takes more conflicts than the target: a key for every metadata index at planning (`cascades_generator.go` `fetchIndexStateSnapshot`) and again on every page (`:2246`).
- The design contradicts itself: (iii) at lines 1235-1237 cites the per-key shape as Java's.
- **Fix:**
  - Measure it: a reader in an explicit transaction scans index I1; concurrently, the state of an unused I2 changes, and in a second case I1's; the reader writes and commits.
  - Port per-scanned-index keys.
  - State what Go's planning-time open adds.

**H2. A bound time.Time is kept at full precision but stored and cached at second precision (lines 595-597, 697-699).**
- Stored text is UTC to the second (`functions/time.go:7,14-15`), and `CAST` to TIMESTAMP truncates the same way (`values.go:4543-4546`).
- The residual comparator compares instants exactly (`predicates/comparisons.go:677-705`). A constant "whose runtime value is the time.Time itself" therefore gives:
  - **Plan-dependent answers.** INSERT `time.Now()` and then `WHERE ts = ?` with the same value: an index lookup matches (the key is the truncated text), a residual filter does not. Today both sides truncate, so it matches.
  - **Cache-dependent answers.** The cache key is the truncated text, but the plan inlines the first instant. So `t` and `t+0.5s` share an entry, and warm and cold executions of the same statement differ.
- A comparison of a DATE column against a time.Time that is not at midnight is unspecified.
- **Fix:**
  - Canonicalize the value at bind so the runtime value, the stored text, the index key and the cache key are one value.
  - Specify the DATE comparison.
  - Test a sub-second value warm and cold, through an index and through a residual filter.

## Medium

**M1. Valuer order (lines 560-567).**
- database/sql checks for a `driver.Valuer` BEFORE dereferencing a pointer; the design dereferences first.
- A `Value()` with a pointer receiver, passed as `&v`, then loses its method set and falls through to the kind rule: a struct becomes 22023, and a named map or slice gets the wrong type.
- Today these values work, via `ErrSkip` and the default converter (`connection.go:970`).
- Fix: at each dereference level, check for a Valuer on the pointer first; a nil pointer whose `Value()` has a value receiver → NULL, as database/sql does.

**M2. Array parameters and nested assignment (lines 578-588, 701-707).**
- **Value-dependent element types.** `Int` and similar kinds are typed per VALUE, so `[]int{1, 3000000000}` gets mixed element types, and an empty `[]int` has no value to type from. Java types an empty array as NONE, with `NONE_TO_ARRAY` (`PromoteValue.java:90,374-380`).
- **Fixed-size byte arrays.** Only slices of bytes become BYTES, so a `[N]byte` becomes ARRAY<INT>. Meanwhile the engine treats a bare `[16]byte` as its UUID representation (`values.go:4521-4526`). State both.
- **Nested narrowing.** Java's promotion lattice recurses into ARRAY elements and RECORD fields (`PromoteValue.java:394-399`). So `[1.5]` or a `[]float64` into ARRAY<FLOAT>, or a DOUBLE struct field into a FLOAT field, is 22000. The design names only the three top-level sources.
- **Incomplete lattice list.** It omits `STRING_TO_ENUM` and `STRING_TO_UUID` (`:93-94`), which decide the stored bytes for bound strings into ENUM and UUID columns.
- Measure one nested case per lane.
