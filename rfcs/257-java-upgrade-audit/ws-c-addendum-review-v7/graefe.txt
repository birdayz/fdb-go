## Findings, most severe first

**1. Low: `validateIndex` is presented as Java's method with Java's messages first, but half of its checks are not.**
- Revision 7 rewrote `validateIndex`. It moved four messages to Java's wording: name, added version, last-modified decrease, last-modified changed. It kept Go's wording for the rest:
  - `index %q type changed` (`metadata_evolution_validator.go:704`); Java says "index type changed".
  - `index %q key expression changed` and `…does not match required` (`:735`, `:739`); Java says "index key expression changed" and "index key expression does not match required".
  - `new index %q drops/adds/changes primary key component positions` (`:749-768`); Java's text has no index name in it.
  - `index %q no longer covers record type` and `…covers new record type…` (`:813`, `:827`); Java says "new index removes record type" and "new index adds record type that is not newer than old meta-data".
  - `index %q field renames result in inconsistent definition…` (`:479`).
- These contradict 7.7 at design `:1210` ("Every check now runs in Java's order with Java's message first"), the doc at `:667`, and the CHANGELOG's "report Java's messages".
- The outcomes still match: Go compares roots by proto, and for Go's classes that agrees with `KeyExpression.equals`. Only the messages differ.
- **Fix:** put Java's text first on each of these, with Go's detail in parentheses as the other messages have it. Add JVM shapes for type, root and positions.

**2. Low: a nil subspace key is refused only when it is set before `AddIndex`.**
- `subspaceKeyErr` is collected only in `addIndexCommon` (`metadata.go:617-619`). Java throws from the setter itself (`Index.java:413-416`).
- So `b.AddIndex(t, idx); idx.SetSubspaceKey(nil); b.Build()` builds without error in Go. So does the same call on an index of an already-built `RecordMetaData`: the call is silently ignored, and the key stays what it was.
- An exported-field literal `&Index{…}` has a nil key. It builds, is maintained under the null item, and `indexToProto` drops the key (`metadata_proto.go:662-665`).
- This contradicts design `:1233`: "a nil key is refused as Java's setter refuses it".
- **Fix:** have `Build` check every index for `subspaceKeyErr` and for a nil key, and pin the set-after-add order.
