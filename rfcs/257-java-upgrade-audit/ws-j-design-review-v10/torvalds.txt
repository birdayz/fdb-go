## MEDIUM

**1. The edited-file route's step (i) cannot load the stored side in its default direction (design :1995-2012).**
- (i) loads the stored bytes "with the union NAMED … and the (d) refusal suspended". In the landed code:
  - `setRecords` refuses any named union that is not the one `fetchUnionDescriptor` finds (`metadata.go:372-375`).
  - Naming a union already skips (d) (`unionNamed`, `metadata.go:385`, `:1509`).
- In shape (d), the pre-upgrade choice (UnionDescriptor) is by definition not the union found.
  - Toward UnionDescriptor, which is the migration's default direction, step (i) fails with "union message UnionDescriptor is not the union descriptor…" before (d) is ever reached.
  - Toward the target's union there is nothing left to suspend.
- The current loader also makes record types from each union field's message type, not by the pre-upgrade loop's `_X`-by-name rule. So "as the pre-upgrade build read them" overclaims.
- The design's own test, "each edited toward each union", would fail as specified.
- **Fix:**
  - Specify an internal loader that takes the named union as THE union.
  - State which of `validateRecords`' union checks run, and against which union.
  - Take the stored side's record types from `legacyUnionRecordTypes` in that direction.

**2. The subspace-key conversion skipped FormerIndex.**
- `formerIndexFromProto` (`metadata_proto.go:914-925`) still reads an absent, empty, multi-item or null key as `nil`.
- Java decodes every FormerIndex through the same `decodeSubspaceKey`. It refuses an absent key too (`FormerIndex.java:64-68`), and a null one with "FormerIndex initialized with null subspace key" (`:51-57`).
- Consequences in Go:
  - It loads metadata Java refuses.
  - `removeFormerIndexData` (`index_state.go:860-885`) then clears `(IndexKey, nil)`, never the dropped index's data.
  - `formerIndexToProto` (`:893-899`) writes `nil` as absent, which Java refuses.
  - The carry rule's re-added-name refusal compares against `nil`.
- **Fix:** read it as Java does, with Java's classes and messages; add unit and JVM shapes and a CHANGELOG line.

**3. The relaxation's reach is unbounded (:2007-2012).**
- A holding field retyped to another message is admitted. Nothing refuses it when an index root or predicate, the primary key or the record count key reads through that field.
- The validator then sees an unchanged root, so the old entries are served under the new decoding.
- Section 4c's own (c) arm makes such an index CHANGED and refuses a primary key over the field. Apply the same rule here, and test it.

**4. A direct `CreateTemplateFromProto` call has no defined lane-check scope.**
- `CreateTemplateFromProto` is public on `api.SchemaTemplateCatalog`.
- "The indexes the save DEFINES" is computed in `Execute` (:1435-1437). A library caller's direct call is therefore either unchecked, contradicting (t) at :2333, or has to re-derive the classes, which duplicates `carryNumbering`'s comparison.
- The "Every template write path" table (:890-897) has no row for it.
- :1404 ("loses nothing another engine wrote") is false for a library caller's bytes: the in-memory catalog stores the loaded object and drops unknown fields.
- **Fix:** either `CreateTemplateFromProto` classifies against its own stored latest with the one shared comparison, or it becomes internal. Add the row.
