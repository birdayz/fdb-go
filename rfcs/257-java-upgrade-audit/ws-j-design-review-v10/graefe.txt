## HIGH

**1. The edited-file route's step (i) can't run for the migration's main arms** (`:1995-2015`, `:2054`).
- **Direction toward the pre-upgrade choice.** Step (i) loads the stored bytes "with the union NAMED … the pre-upgrade choice or the target's; the `SetRecordsWithUnionName` path". But `setRecords` refuses any name other than the one `fetchUnionDescriptor` finds (`metadata.go:367-376`; the design itself says so at `:1694`). So loading (d1)/(d2) under UnionDescriptor, which is the migration's default direction, is refused.
- **(a) and (b).** Their stored sides fail "Union descriptor is required".
- **(c).** Its stored side fails the unsigned check (`metadata.go:380`). Its output would also fail Java's validator, which admits only int32→int64 and sint32→sint64 (`MetaDataEvolutionValidator.java:331-339`). That is not covered by the route's "ONE relaxation" (`:2007`).
- **Contradiction.** Yet `:2015` says "the migration's own outputs take the same route", while `:2054` still says the route "reads the stored proto RAW (the refusing loader cannot)". That is two specs.
- **Framing.** A current-rules load would also compare today's type-based framing with itself. The pre-upgrade loop framed by name first (`_X`).
- **Fix:**
  - Specify an internal stored-side builder: union by name, bypassing `fetchUnionDescriptor`, with record types from `legacyUnionRecordTypes`.
  - List, arm by arm, which checks are suspended and which validator relaxations apply (same-width signed retype, the usage option, removal of RecordTypeUnion). Alternatively, validate migration outputs by re-applying the migration and keep the validator for edited files only.
  - Keep one spec.
  - Test (d1) toward UnionDescriptor, (a) and (c) through the route.
