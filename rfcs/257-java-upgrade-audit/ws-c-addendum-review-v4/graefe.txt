## Findings, most severe first

**1. Medium-low (wire): `Build` checks that a target exists but not that it is the metadata's own object.**
- Java's `validateIndexSetting` ends with `index != metaData.getIndex(name)`, which throws a `MetaDataException` (`OnlineIndexer.java:880-883`).
- Go checks the name only (`online_indexer.go:801`, a plain `fmt.Errorf`). It also returns a plain `fmt.Errorf` where Java throws `MetaDataException("index must be set")` (`:862-864`).
- Go then never replaces the targets with the metadata's objects. So a hand-built target with the right name and a different subspace key would build its entries and ranges under the caller's key, while the state and publication go by name.
- That is the source-index problem 7.4 fixed, on the write side. It is also the one check of the method 7.4 says `Build` now follows that is missing.
- Fix: refuse a target that is not the metadata's object, with Java's class and message. Pin it.

**2. Low: standalone `MergeIndexes` has Go-only behaviour that is not declared.**
- Java creates a heartbeat only in the build session's stamp step (`IndexingBase.java:457`). Its standalone merge (`OnlineIndexer.java:409-410` → `:1085-1096`) therefore passes `updateHeartbeat` with `heartbeat == null` (`:969-972`): it writes no heartbeat and checks no state.
- Go gives the merge a heartbeat (`indexing_merger.go:169`). Through `refreshFollowupHeartbeats` (`online_indexer_queue.go:443-481`), that has two effects:
  - Over a WRITE_ONLY target it runs exclusive admission and writes a live "explicit index merge" key, which locks out a Java builder.
  - Over a DISABLED target it returns `RecordCoreStorageError`.
- The new DIVERGENCES.md bullet covers only a build session, and the section still ends "No wire bytes differ".
- That bullet also leaves out one Java case: with `SetMarkReadable(false)`, Java's session succeeds after the last range and leaves the target DISABLED.
