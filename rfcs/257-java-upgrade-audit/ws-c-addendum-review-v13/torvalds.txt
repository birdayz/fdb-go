## Findings (all Low, most severe first)

**1. The VECTOR option check does not parse the way the new text says it does.**
- `vector_index_validation.go:32-35` and the DIVERGENCES VECTOR entry say the parse cause is "a value Java's `Integer.parseInt` or `Double.parseDouble` refuses".
- The code parses with Go's own functions instead: `strconv.Atoi` (`:51`, `:72`) and `strconv.ParseFloat` (`:85`). The repo already has Java's parser, `javaParseInt` (`java_parse.go:46`), and DIVERGENCES `:3153` describes a port of `parseDouble`.
- The verdicts then differ from Java's:
  - `hnswM="2147483648"`: Go builds, Java refuses. Go stores meta-data Java cannot open.
  - Unicode digits, `"1.5d"`, `" 0.5 "`: Java builds, Go refuses.
  - `"inf"`, `"nan"`: Go builds, Java refuses.
- The non-parse cause (`IllegalArgumentError`) carries Go's text, and DIVERGENCES does not say so.
- **Fix:** use the Java parsers and add JVM rows for these inputs.

**2. A new global cache never shrinks.**

- **Fix:** compute the flag once per `RecordType` when meta-data is built, as `unionFieldNumber` is.
