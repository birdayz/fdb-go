The admission design should therefore:

1. Resolve and validate all `VECTOR` metadata at metadata construction/open/evolution boundaries.
2. Preserve an immutable resolved engine/configuration on the store or maintainer.

**The depth-first implementation order should close dependencies before exposing their consumers.**

1. **Admission branch:** typed key descriptors → duplicate detection → pure effective configuration → engine resolution → evolution checks → pre-mutation admission across metadata/store/queue/decorated paths. Keep GuardiANN unavailable until its implementation is ready.
2. **Common primitive branch:** operation RNG/UUID helpers → Java vector-engine cosine/comparator behavior → common result representation. Reuse WS-A quantization and existing inverse rotation.
3. **Storage branch:** complete parsed-node representation → three/four-field codec → all single/batch/edge/preload caches → compact writer → insertion/pruning/deletion preservation. Establish lossless mixed-writer storage before higher APIs.
4. **Mutation branch:** Java insert-if-absent alongside the preserved direct-Go upsert → updated operation seeds in first insert/statistics/delete → sample UUID writes and existing conflict protocol.
5. **Read primitive branch:** provenance-aware reconstruction → fetch → limit-two cardinality → diagnostic result scan.
6. **Search branch:** shared objective-based beam search → layer-appropriate vector fetching → distance/PK ordering → ordinary kNN → ring search.
7. **Traversal branch:** spatial restrictions → outward iterator state machine → quick-start suppression/readiness/cancellation → centroid-HNSW interface.
8. **Record adapter branch:** admitted HNSW engine → tri-state scan options through planning/execution → optional vector payloads → continuation replay → timer listeners → synchronous maintenance assertions.
