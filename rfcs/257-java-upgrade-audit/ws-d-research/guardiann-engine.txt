**Identity and byte provenance are algorithmic dependencies.**

The signature algorithm is SHA-256 over `RealVector.getRawData()`, taking the first 16 bytes, then stamping:

```text
signature[6] = (signature[6] & 0x0f) | 0x80
signature[8] = (signature[8] & 0x3f) | 0x80
```

That is version 8 with the IETF variant. Hash stored representation bytes—including encoding/calibration—not decoded coordinates, JSON, tuple-wrapped bytes, or a requantized reconstruction. Preserve already encoded RaBitQ bytes through reads, task payloads and rewrites. [Signature implementation](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/StorageAdapter.java:540).

Use a representation carrying raw bytes, encoding and coordinate provenance, with lazy decoded coordinates. WS-A’s `hnswVector` demonstrates why the encoding tag alone is insufficient: plain access-info bytes can already be transformed, while plain node bytes still require the current transform. Reuse that distinction, not HNSW’s entire mutable graph object. [Current provenance/write boundary](/home/birdy/projects/fdb-go/pkg/recordlayer/hnsw.go:211).

Other identity contracts:

- `VectorId` is `(PK, UUID)`. Ordering compares PK, then Java UUID ordering; Java’s signed-long UUID comparison differs from unsigned tuple UUID key order.
- Deterministic vector UUID is Java `UUID.nameUUIDFromBytes(PK.pack())`: MD5 version 3 with **no namespace prefix**. Reinserted identical PK therefore repeats this UUID in deterministic mode.
- Operation RNG seed starts at zero and folds every unsigned packed-key byte through `splitMixLong(seed XOR byte)`. UUID seeds fold its 16 big-endian bytes.
- Deterministic random UUID generation consumes two `nextLong` values and stamps version 4. Split child RNGs before asynchronous scheduling.
- Task priority clears the UUID’s leading bit for high priority and sets it for normal priority, matching tuple key ordering. Bounce re-enqueue uses ordinary `randomUuid`, not priority restamping.

**Running statistics and lifetime peak must remain separate concepts.**

Port `RunningStats` as an immutable value with identity `(0,0,0,-∞)`:

- Add uses Welford’s two-delta update.
- Remove uses inverse Welford; removing the final element returns identity. Otherwise the distance maximum remains stale.
- Combine uses the parallel/Chan formula and maximum of both maxima.
- Subtract uses inverse combination; larger population fails; equal population returns identity. Clamp only `-1e-12 < M2 < 0`; subtraction rejects a remaining negative M2.
- Empty mean/population variance/max return NaN; sample variance requires at least two observations.

Preserve expression order and IEEE values in the wire codec. Do not replace the stored maximum with a recomputed percentile or current maximum. [RunningStats.java:45–212](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/RunningStats.java:45).

Cluster primary population is `stats.n`; `lifetimePeakPrimaryCount` is independently maintained as `max(oldPeak,newN)` and survives shrinkage, including emptying. Constructor invariants reject underreplicated count above population and peak below population.

The final merge threshold is:

```text
max(primaryClusterMin, floor(mergeMaxEverFraction * lifetimePeakPrimaryCount))
```

Merge eligibility is **strictly below** that threshold, requires no split/merge or collapse flag, and requires centroid cardinality MULTIPLE. A final empty cluster remains; no impossible one-to-zero merge is queued. **Insert, assignment, replication and delete need their own GuardiANN primitives.**

Insert reads access information and current PK metadata. It bootstraps the first centroid/cluster when access information is absent. Otherwise, with in-transaction maintenance enabled, it attempts one deferred task **before** the existing-PK no-op decision. This sequencing matters for quiet writes and task accounting. [Insert.java:185–235](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Insert.java:185).

The assignment path is:

1. Transform the incoming vector and obtain the active quantizer.
2. Traverse nearby centroids through outward HNSW search, bounded by the insert candidate count.
3. The first centroid is home. Candidate collection stops at the first failed replication-priority predicate; it does not skip that candidate and continue.
4. Write tag-5 identity/covering metadata.
5. Add the primary reference and its centroid distance to running statistics.
6. Select replicas using priority and relative-neighborhood occlusion, then write references and metadata deltas.
7. Schedule split/reassign work through the shared metadata-update primitives.

For candidate distance `d`, home distance `h`, candidate-cluster statistics `(n,μ,σ)`:

```text
r = h / (d + 1e-12)
z = 0                                  if zWeight == 0 or n < statsMin
    max(0, (h - μ) / (σ + 1e-12))       otherwise
priority = ratioWeight*r + zWeight*z
```

The executable callers use the **candidate cluster’s statistics**. Occlusion rejects a candidate when its centroid is strictly closer to an already selected replica centroid than the vector is to that candidate. The home is not inserted into the selected-replica set. Insert has no independent “retain 100 replicas” truncation; its candidate bound controls work. Maintenance has its own truncation rules. [Insert assignment](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Insert.java:260), [priority/occlusion](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/StorageAdapter.java:477).

**Search semantics are deliberately bounded and can underfill.**

KNN performs the following stages in order:

1. Traverse at most 48 centroid candidates by default.
2. After the first 16, stop the retained prefix when distance/nearest-distance exceeds 1.5. Preserve zero/NaN comparison behavior.
3. Scan references in retained clusters and keep `max(k,ceil(1.4*k))` using the comparator `(Double.compare(distance), VectorId)`.
4. Expand only collapsed references retained by that first pool; substitute member identities and apply the bounded pool again.
5. Memoize current metadata reads by PK; retain only matching UUIDs.
6. Take up to `k` surviving results, preserving candidate order.

There is no refill after stale filtering. Do not scan additional clusters to “repair” underfill. Comparator-based distinctness is not equivalent to an early PK-only deduplication. The executable path also does not implement the centroid-ball pruning suggested by some higher-level prose. [KNN stages](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Search.java:189), [pool/expansion](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Search.java:338), [stale filtering](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/Search.java:415).

Ordered retrieval is a separate algorithm: bounded centroid traversal, collapsed expansion **before** vector cutoff, bounded almost-sorting, current-metadata filtering, PK deduplication, then limit. At equal distance, a null minimum PK retains the candidate; otherwise PK must be greater. The almost-sort window fills to its bound, emits the minimum, and refills on subsequent demand. It is not globally sorted: Java’s fixture `[2,3,4,1]` with window 2 yields `[2,3,1,4]`. Preserve cancellation and close propagation. Shared scheduling rules deserve one implementation:

- Positive primary growth beyond max schedules split/merge unless split/merge or collapse is already pending.
- Reassign requires no existing reassign, excludes a target that is itself a cause, and is triggered by nonempty causes, excess replica writes, or excess underreplicated primaries.

**KMeans and the evaluator need direct numerical ports.**

SPFresh currently clamps `k`, seeds using modulo of `nextLong`, performs chunked reductions, repairs an empty cluster by changing an assignment, and has an optional build convergence fraction. Those choices differ materially from this Java implementation. Keep [spfresh_kmeans.go:110–309](/home/birdy/projects/fdb-go/pkg/recordlayer/spfresh_kmeans.go:110) unchanged.

The separate KMeans port must preserve:

- Validation before the `k=1` fast path: nonempty compatible population, `k≥1`, `n≥k`, iterations ≥1, restarts ≥0 and nonnegative balancing weight.
- Euclidean and cosine support; do not silently substitute squared-Euclidean or dot-product engines for unsupported clustering metrics.
- `k=1`: ordered mean, cosine normalization or its near-zero fallback, no random draws.
- Initial run plus `maxRestarts`; KMeans++ uses Java bounded integer selection, metric-specific objective weights, cumulative selection, and uniform fallback for zero total weight.
- Lloyd assignment with strict `<` ties favoring earliest centroid.
- Optional shuffled assignment/overflow-size penalty when balancing weight is positive. GuardiANN invokes it with weight **0**, but the helper should still port its complete contract.
- Ordered coordinate accumulation; empty/meaningless cosine centroids reseed to the earliest worst-served vector against the old centroids.
- Stop on zero changed assignments before recentering.
- Always perform final assignment; do not perform a final recenter.
- Select strictly lower objective across runs; preserve encoded-estimator versus ordinary-coordinate objective paths.

The evaluator computes both partitions independently:

- Sizes, SSE, smallest fraction and largest fraction.
- Raw imbalance `Σ(size−n/k)²/n²`; relative imbalance multiplies by `k/(k−1)` for `k>1`, otherwise zero.
- Per-child interpolated 95th-percentile radius; maximum of those radii.
- Separation = minimum centroid separation divided by `max(maxRadius95,1e-12)`.
- Euclidean margins from competing centroid distances; cosine margins from clamped raw dot products.
- Median/p10 margin and low-margin rate.
- The default Euclidean low-margin threshold uses an overall p95 selected through a top-tail heap, not the same interpolation used for per-child radii.

Euclidean evaluator SSE uses direct squared coordinate distance, while KMeans’ optimized Euclidean objective can square an estimator distance. Preserve that difference. [Statistics/margins](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/PartitionEvaluator.java:310), [SSE/percentiles](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/PartitionEvaluator.java:681).

Scoring is:

```text
gainSSE = (oldSSE − newSSE) / max(oldSSE, 1e-12)

score = α*gainSSE
      + β*(newSeparation − oldSeparation)
      − γ*max(0, newRelativeImbalance − oldRelativeImbalance)
      − δ*max(0, newLowMarginRate − oldLowMarginRate)
```

Undefined separation/margin terms are mapped as Java specifies. Gate order is minimum-child INVALID; excessive imbalance KEEP; for `k≥2`, separation and low-margin KEEP gates; then minimum SSE gain; then minimum score; otherwise ACCEPT. Single-child candidates skip separation/margin gates.

Evaluator defaults are SSE gain `.1`, separation `.3`, maximum low-margin rate `.25`, child fraction `.015`, relative imbalance `1`, automatic low-margin threshold `-1`, weights `1/.5/1/.75`, and score `.05`. GuardiANN overrides child fraction `.1`, relative imbalance `.36`, and split γ `3`; merges retain γ `1`. [Scoring/gates](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/PartitionEvaluator.java:87), [defaults](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/kmeans/PartitionEvaluator.java:929), [GuardiANN overrides](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-extensions/src/main/java/com/apple/foundationdb/async/guardiann/SplitMergeTask.java:1194).
