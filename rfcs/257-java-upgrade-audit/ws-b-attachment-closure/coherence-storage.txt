**P2 — A handle can publish pre-clear state after the context range clear has completed.**

[clearRangeWithIndexStateViews](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:316) protects only already-registered views. However, an unchanged-version [Open](/home/birdy/projects/fdb-go/pkg/recordlayer/store_builder.go:1412) loads `indexStates` without necessarily attaching a view. Its first subsequent state access [registers that previously loaded map](/home/birdy/projects/fdb-go/pkg/recordlayer/store.go:178), and [indexStateView](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:303) accepts it without checking whether a clear intervened.

A sequential reproduction using the context-clear API:

1. Commit an **empty, noncacheable store** with index `I` DISABLED.
2. In a fresh context, `Open()` that store with unchanged metadata, without calling a state getter. The handle contains `I=DISABLED`; no shared view exists.
3. Call `ctx.ClearRange(store.IndexStateSubspace())`. The persisted state key disappears, but there is no registered view to update.
4. Call `store.MarkIndexDisabled("I")`. Initialization publishes the old DISABLED map, so the [unchanged-state branch](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:254) returns without restoring the state key.
5. Save a record. Maintenance observes DISABLED and skips the index. Commit and cold-reopen: the absent state key means READABLE, although the saved record has no index entry.

Starting empty means the clear itself does not expose an incomplete index; the subsequent stale decision causes the corruption. No concurrent goroutines or direct transaction mutations are needed.

The new ordering regression [explicitly attaches both handles before clearing](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state_test.go:2588), so it cannot detect this case. Tagged Java’s [markIndexNotReadable](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/main/java/com/apple/foundationdb/record/provider/foundationdb/FDBRecordStore.java:3704) reads the transaction’s actual state key before deciding whether the transition is redundant.

**Required correction:** coordinate initial state loading/publication with context clearing, including loaded-but-unattached handles and loads already in flight. Prevent a map predating a clear from becoming authoritative. Add a real-FDB clear-before-first-access regression asserting the transition result, raw state bytes, maintenance behavior, and cold-reopened state.
