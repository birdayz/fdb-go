## MEDIUM

**1. The stored side is framed name-first, but everything that checks it is type-first** (design `:2139`, `:2170`, `:2207`, `:2063`).
- Pre-upgrade Go wrote and read records as raw bytes by field number, parsed with the framed type's descriptor, whatever the field's declared type (`e48f5b496:store.go:2052-2077`, `:2121-2196`). So a `_X` field typed by another message, or a scalar `_T`, did carry data.
- Step (ii)'s validator does not follow that framing. It pairs union fields by declared message type (Go `metadata_evolution_validator.go:319-338`, Java `MetaDataEvolutionValidator.java:197-207`). It also refuses any non-message old union field. That undoes the suspension step (i) grants: scalar-framed shapes are refused at (ii), and a record type framed by name is compared through the wrong message.
- The migration's output check and step (iii) compare only the UNION. The current loader frames each field by its message type (`metadata.go:392-401`). So a `_X` field typed by a nested `Outer.X` loads under a different descriptor, and nothing notices.
- "The records carry only union field numbers, which do not change" is therefore not the whole safety argument for arms (a), (b) and (d).
- **Fix:**
  - Require the output's framing to equal `legacyUnionRecordTypes`' framing, field number by field number (record-type name and descriptor), in the migration's output check and at (iii).
  - Declare that (ii) refuses scalar-framed fields, or specify a validator mode that pairs by the stored framing.
  - Pin the nested-`X` and scalar-`_T` shapes.

**2. R1's reach bound is false for predicates** (`:2157`).
- `SetPredicateProto` compiles without a descriptor (`index.go:600-620`), and `Build` never checks index predicates against record types.
- So a sparse index whose predicate reads the removed holding field still loads. It then stays READABLE without a rebuild while its predicate now evaluates differently.
- **Fix:** refuse R1, or class the index CHANGED, when any predicate reads through the removed field. Test it.

**3. The restore's carry-invariant check is too weak** (`:618-627`). It compares record-type keys and union numbers only for names both versions define. It misses two things:
- **Index definitions.** A predicate-only difference with equal versions passes the rebind validator. That is the design's own reason for refusing a restore nothing binds (`:556-560`). Tenants on fresh v1 are then repaired onto the restored v3.
- **Inverse collisions.** Two different names on one key or union number are admitted as a rename, because the rebind validator does not disallow renames (`fdb_store_catalog.go:352-353`).
- **Fix:** require section 4's carry compatibility in both directions:
  - a one-to-one map of key and union number;
  - each index EQUIVALENT, or its last-modified version above the lower version's metadata version;
  - former-index keys disjoint from the other side's live indexes.
  
  Test both holes.

**4. `CreateTemplate` does not own the `v′ > latest` refusal.**
- The refusal lives only in the save action (`save_schema_template.go:36-43`). The FDB `CreateTemplate` refuses only an exact duplicate (`fdb_template_catalog.go:142-150`).
- A library caller's `CreateTemplate(t, v′ < latest)`, for a version that is not stored, is carried and written. The guard's range starts at `(t, latest+1)` (`:499`), so it never sees a dangling `(t, v′)` binding. A pre-upgrade `DeleteTemplateVersion` can leave exactly such a binding, and this call re-issues the version.
- **Fix:** move the refusal into `CreateTemplate`, or have the guard read `(t, v′)` as well. Test it.
