## HIGH
**H1. Shape (g) compares against the wrong Java quantity** (design `:2334-2341`).
- **What the design says:** today's key is "Java's preferred field (`_T` by name, else the larger number, `RecordMetaDataBuilder.java:878-887`)".
- **What Java and current Go do:**
  - That preferred field is the field records are written under.
  - The implicit record-type key is the SMALLEST matching union field number: `RecordType.java:171-179`, Go `metadata.go:413-415`.
  - The pre-upgrade key was the last field the name-first loop framed (e48f5b496 `metadata.go:331-376`, `:1837`).
- **As specified, the refusal misses real misreads:**
  - `T _T_old = 1; T _T = 5`: the pre-upgrade loop skips `_T_old`, since no top-level `T_old` exists, so its key was 5. The preferred field is also 5, so the file loads. Today's key is 1, so pre-upgrade keys prefixed 5 are read under 1. This is Java's deprecate-a-union-field pattern.
  - `T a = 1; T b = 2` fails the same way.
- **It also refuses a file whose keys agree:** `T _T = 5; T b = 3` has key 3 in both builds.
- **The remedy is unsafe or unreachable:**
  - "Explicit key = pre-upgrade number" re-keys rows that a type-first build (Java, or any build after the upgrade) wrote.
  - It needs a save, and the ordinary save's load of the stored side refuses. The edited-file route would work only if its as-framed load reproduces the last-field key, which the design never states.
- **Fix:**
  - compare the last framed field with the smallest one;
  - route the explicit-key remedy through the edited-file route, stating the key that route's load of the stored side produces;
  - scope the remedy to stores only pre-upgrade Go wrote;
  - pin both examples above.

**M2. Check (iii)'s "either order" for WIDENED cannot be reached at an equal last-modified version** (`:695-700`, test `:729-731`).

- Both directions store the same tuple bytes, so this fails closed and strands the bound schemas.
- **Fix:** make the restore's widening arm symmetric, or state the refusal and test it.
