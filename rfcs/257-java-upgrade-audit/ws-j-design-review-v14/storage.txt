## HIGH
**H1. The store-open probe refuses Java stores, and its remedy re-keys them** (`:2520-2533`, (y) `:3146-3148`).
- **The skip rule is too narrow.** It skips only when another type has the pre-upgrade number as an EXPLICIT key. Two other cases find records under that number:
  - **(f) and (g) together:** `{T a = 1; Y _T = 5}`, with top-level T and Y. Pre-upgrade Go keyed T at 5; the target keys Y at 5 by the implicit rule. The probe for T reads Y's rows.
  - **A type U whose primary key does not start with `recordType()`:** a row with `id = 5` sits in the same range.
- **Mixed stores:** a store both Java and pre-upgrade Go wrote also trips the probe.
- **The remedy is stated unconditionally.** An explicit key of 5 is metadata Java reads too, so Java-written T rows under 1 vanish for both engines. One `FDBMetaDataStore` can also serve stores that different engines wrote.
- **Fix:**
  - probe only when `RecordMetaData.primaryKeyHasRecordTypePrefix()` holds for the whole metadata (Java `:511-513`);
  - skip when any type's target key, implicit or explicit, equals the number;
  - have the route read under today's number (limit 1) and refuse if it finds a row;
  - make the error's remedy conditional, and declare the shared-metadata-store case.

**H2. 3.6's "Function not defined" at load locks Go out of Java stores it opens today.**
- **Where the names come from:** Java resolves function names through its ServiceLoader registry (`FunctionKeyExpression.java:117-131`). The Lucene and Geophile spatial modules register their own functions, and so can applications.
- **What Go does today:** it loads any function name (`key_expression_proto.go:391-400`). It refuses an unknown index type only when it looks up a maintainer (`store.go:1346`), not at load.
- **After 3.6:** any Java store with a Lucene, spatial or application-function index fails to open in Go. That is the same trade-off v14 used to withdraw `LegacyFramingError`, and the design neither states nor declares it.
- **The arity check has nothing to read.** Go's registry maps a name to an evaluator with no bounds (`key_expression.go:1531-1546`).
- **Fix:** decide it — load and fail per index, or refuse and declare it as an owner item. Define where each function's arity bounds come from, and how the public `RegisterFunction` supplies them.

## MEDIUM
**M1. Four of 3.6's six shapes never reach the constructors on stored bytes.**
- **Why:** `field_name`, `fan_type` and the Function's fields are proto2 `required` (`record_key_expression.proto:36-37`, `:99-100`). Java parses stored bytes with `parseFrom` (`FDBMetaDataStore.java:329`, `RecordLayerStoreSchemaTemplateCatalog.java:221`), which refuses a missing required field at parse. Go's `proto.Unmarshal` (`metadata_store.go:146`, `:171`, `fdb_template_catalog.go:286`) checks required fields too.
- **Consequence:** on bytes, "Invalid fan type 7" is unreachable in Java, because an unknown closed-enum value leaves the required field unset. "Invalid null interpretation" (`Key.java:418`) is unreachable for the same reason.
- **Fix:**
  - pin the parse-level outcome on both engines;
  - keep the constructor-level refusals for protos built in memory;
  - say which layer the JVM oracle measures;
  - add the wrapping 3.6 omits, the record count key (`RecordMetaDataBuilder.java:260-265`) and the counter faults (`:292-295`).
- Go's handling of closed enums is a hypothesis; measure it.

**M2. The design names the wrong explicit-key field** (`:2528`, `:2681`, `:2687`).
- **The problem:** it says `record_type_key`, which is the message option (`record_metadata_options.proto:47`). Java's stored load ignores that option (`setRecords(proto)` passes false, `:381-383`; options are read only at `:897-905`), and Go ignores it on both paths.
- **Fix:** the route, the migration and the error text must write `RecordType.explicit_key` (`record_metadata.proto:180`, read at `:233-234`).
- **Related:** 4c's "`SetRecords` keys each type as Java keys it" (`:2480`) is false for a file carrying the option, because Java's `setRecords(FileDescriptor)` processes it (`:420-421`). That divergence is undeclared.

**M3. The storage and operator view is incomplete.**
- **Unstated:** whether the probe is a snapshot or serializable read, its conflict range, and its cost on every open of a Java store that is never edited.
- **Nothing to find the affected stores:** operators get no detector for stores in shapes (f) and (g), and no warning at load.
- **Rolling upgrades:** mixing pre-upgrade and new nodes on such a store writes in divergent framings. That is undeclared.
- **In-process metadata:** its remedy is `SetRecordTypeKey`, not the route, which cannot reach it.
