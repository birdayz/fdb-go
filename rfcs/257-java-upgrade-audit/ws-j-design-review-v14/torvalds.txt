## HIGH
**H1. The store-open probe refuses Java stores Java opens** (`:2520-2533`).
- The probe reads the range `(records, N_pre)` with limit 1 and treats any hit as a legacy T row.
- Java allows mixed primary-key shapes: `primaryKeyHasRecordTypePrefix` requires *every* type to carry the prefix (`RecordMetaData.java:511-512`).
- So if U's primary key is `field(id)`, a U record with id = N_pre sits in that range. Take `{T _T_old=1; T _T=5}` plus U: any U with id 5 fails the open.
- That is the lock-out that `LegacyFramingError` was withdrawn to avoid. The skip condition covers only an explicit-key collision.
- **Fix:** run the probe only when every type's primary key begins with `recordType()`, or decode the hit and confirm it holds a T union field. Pin a mixed-shape Java store with a colliding id that opens.

**H2. 3.6's "Function not defined" refusal at load would lock Go out of stores whose Java writer had Lucene or spatial on its classpath.**
- Java's registry depends on the classpath: `LuceneFunctionKeyExpressionFactory.java:42-52` and `GeophileSpatialFunctionKeyExpressionFactory.java:42-45` register their own function names.
- Go registers neither. Today Go loads such metadata (`functionFromProto` builds any name) and fails closed only when it maintains the index (`UnknownIndexTypeError`, `store.go:1346`).
- After 3.6 the whole store is unopenable.
- The design never mentions this: a search for `lucene|geophile|spatial|classpath|registry` finds 0 hits; control: "Function not defined" is at `:1615`.
- Arity is also unplaced. Go's registry is `map[string]FunctionEvaluator`, with no bounds (`key_expression.go:1530-1545`), and exported `RegisterFunction` has no bounds parameter either.
- **Fix:** either register Java's optional-module names with their arities as load-only entries (load succeeds, evaluation fails), or declare the lock-out. State where the bounds live and the API change.

- **`NOT_NULL` null interpretation:**
  - `fieldFromProto` collapses it to `NOT_UNIQUE` (`:251-258`), and the Go comment at `key_expression.go:317-325` says "Go does not model NullStandin".
