## MEDIUM

**M1. The NaN write fix covers only CAST.**
- Go's MIN and MAX return `math.NaN()` (`0x7ff8000000000001`) for any NaN operand (`streaming_cursors.go:2157-2168`, through `aggMinMax` :826-843). The target's MIN_D and MAX_D are `Math.min`/`Math.max` (`NumericAggregationValue.java:688, 693`), which return an operand's NaN.
- So `INSERT … SELECT MIN(d)` writes bits that a Java index probe misses.
- The claim at :1128-1129, "whatever bits its producer gave it", does not hold for these producers. (SOURCE)
- **Fix:** list every non-test `math.NaN()` in `executor/` and `values/` (with a positive control), fix each, and add an oracle row.

**M2. The tie-row text overcorrects (:2853-2860).**
- It says inverting REWRITING's `deepHash` reddens EVERY tie row and inverting PLANNING's `costExprHash` reddens NONE.
- But the list includes `in_cast_null_join_inner_empty`, a join-nesting tie that 4.1 and TODO.md:4571 place in PLANNING.
- Section 8 already separates the two classes.
- **Fix:** split the pins by the phase that decides them, and predict the mutation outcome per row.

**M3. The canonical-text property that 4.3 rests on (:1459-1466) fails through type-merging operators.**
- CASE is a `PickValue` over unpromoted branches, typed by `CommonValueType`→`MaximumTypeOfMany` (`walk.go:649-661`, `scalar_function_catalog.go:504-545`). IF and IFNULL are typed the same way.
- So a DATE branch holds date text under a TIMESTAMP type, and comparing it with midnight TIMESTAMP text gives `=` FALSE and `<` TRUE.
- Item 5 says their typing "does not change here", and the producer list omits them.
- **Fix:** inject the promotion into those branches, and add them to the producer list and the property test.

**M4. The guard narrowing is general, but its evidence is not.**
- `len(probeCorr) > 0` (the prototype's `planner.go:1482`) admits ANY compensation whose probe is correlated to one outer alias and whose residual is correlated to another, not only explode shapes.
- The narrowing is consistent with the stated hazard: `matchBoundPrefixIsCorrelated` gates only PK-intersection candidacy (`planner.go:1194`), and constant-pool aliases are subtracted in both places.
- But the planned guard tests are classification unit tests. The evidence is the corpus (1 change), seed 17 and the existing suites, and none of them has rows for a probe correlated to o1 with a residual correlated to o2.
- **Fix:** add FDB row tests of that non-explode three-way join (both nestings, with and without ORDER BY, resumed from a continuation), and a rowdiff lane run of join seeds with GUARD against NONE.

**M5. The planning-cost baseline is omitted.**
- `wse12-proto.out:39-54` records seed 17 at 23,459 tasks on today's tree (NONE), 42,723 for the explode port (BASE) and 44,932 with the full design (GUARD): +92%.
- The design quotes only +2.8% and +5.2% over BASE and frames 42,723 as the starting point (:816-822, :904).
- A pin "under the budget" leaves 3.3x headroom.
- **Fix:** price the design against NONE and pin seed 17 tightly.

**M6. The DATE repair is misdescribed (:1551-1554).**
- An UPDATE whose CAST fails on one row fails the whole statement; it does not leave that row "as it is".
- Under the UNIQUE index this section says admits both spellings of a day, the repair raises 23505.
- Declare both, with a repair that only touches timestamp-text rows.
