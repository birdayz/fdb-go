1. **P1 — State transitions on a lazily built store can bypass header initialization permanently.**

   [`MarkIndexDisabled`](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:243) now uses `readIndexState`, replacing the getter that performed lazy initialization. The new helper reads only the index-state key. A store returned by [`Build()`](/home/birdy/projects/fdb-go/pkg/recordlayer/store_builder.go:1490) therefore still has no loaded header when `setIndexState` runs.

   `setIndexState` creates a partial `indexStates` map and [conditionally invalidates the metadata stamp](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:380) using the still-nil header. Subsequent [lazy initialization](/home/birdy/projects/fdb-go/pkg/recordlayer/store.go:174) sees the non-nil map and permanently treats the store as loaded.

   Concrete sequence: existing cacheable store → fresh `Build()` → `MarkIndexDisabled()` → commit. Index state/data change without the required cache-stamp invalidation. Reusing that store also leaves its header absent: [`validateRecordUpdateAllowedLocked`](/home/birdy/projects/fdb-go/pkg/recordlayer/store.go:250) permits record updates when the header is nil, so a persisted record-update lock can be bypassed.

   Java explicitly [preloads store state before this transition](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/main/java/com/apple/foundationdb/record/provider/foundationdb/FDBRecordStore.java:3691).

   **Fix:** ensure full, error-propagating header/state initialization before state mutations, while retaining transaction-visible serializable state reads. Add `Build()`-based transition regressions covering independently warmed cache invalidation, persisted record-update locks, and header-read failures.

2. **P1 — Operational state checks remain stale in vector scans and aggregate selection.**

   [`ScanVectorIndexWithPrefix`](/home/birdy/projects/fdb-go/pkg/recordlayer/vector_index_maintainer.go:1338), [`SearchVectorIndexWithPrefix`](/home/birdy/projects/fdb-go/pkg/recordlayer/vector_index_maintainer.go:1381), and [aggregate index selection](/home/birdy/projects/fdb-go/pkg/recordlayer/aggregate_function.go:219) still use `IsIndexScannable`/`IsIndexReadable`. Those reach the [cached getter](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:74), which neither refreshes transaction-visible state nor adds a state-key conflict.

   Open two store objects in one context, disable an index through one, then query through the other: the second object can still select the cleared index; a COUNT aggregate can consequently return zero instead of rejecting the unavailable index.

   Across transactions, a snapshot vector scan or snapshot COUNT aggregate on a noncacheable store can commit an unrelated sentinel after a concurrent disable commits, without the required index-state conflict. Initial state loading is snapshot, and disabling does not change the header. Java’s [state getter explicitly adds that conflict](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/main/java/com/apple/foundationdb/record/provider/foundationdb/FDBRecordStore.java:4241).

   This is an uncovered WS-B integration dependency, including in unchanged callers: the [approved design requires transaction-visible state and serializable conflicts for operational scans and negative decisions](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-b-design.md:94).

   **Fix:** route these error-capable paths, and corresponding record-function selection, through the new state-read helper; preserve requested data isolation. Add same-context two-store tests and pinned-version concurrent-transition tests with observable commit outcomes.

3. **P2 — New TEXT body validation does not cover multi-type indexes.**

   [`AddMultiTypeIndex`](/home/birdy/projects/fdb-go/pkg/recordlayer/metadata.go:603) stores indexes spanning two or more types in `rt.multiTypeIndexes`. The new [descriptor collection loop](/home/birdy/projects/fdb-go/pkg/recordlayer/metadata.go:796) visits only `rt.indexes`, with a separate universal-index loop. Consequently, the [TEXT body validator](/home/birdy/projects/fdb-go/pkg/recordlayer/metadata.go:1302) receives no field lists for multi-type indexes and silently skips validation.

   A TEXT index associated with two record types can therefore build with an integer body field. Java [validates every covered record type](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/main/java/com/apple/foundationdb/record/metadata/MetaDataValidator.java:182) and rejects that body. In Go, the [runtime TEXT maintainer silently ignores non-string values](/home/birdy/projects/fdb-go/pkg/recordlayer/text_index_maintainer.go:303), allowing successful saves without corresponding text entries.

   **Fix:** validate every covered `(index, record type)` pair, including multi-type associations. Retain positive two-type string-body coverage and negative mixed-type, repeated-body, and missing-body cases, with Java comparison.

4. **P2 — The deletion acceptance matrix is incomplete.**

   The [approved requirements](/home/birdy/projects/fdb-go/rfcs/257-java-upgrade-audit/ws-b-design.md:70) include unknown-field headers, both commit orders against creation/cacheability changes, and actual versioned-save-then-delete behavior.

   The retained [16-case matrix](/home/birdy/projects/fdb-go/pkg/recordlayer/store_api_test.go:411) varies cacheability, warmth, commit order, and **header-field update versus ordinary record write**. It does not exercise creation or cacheability-toggle races. The [header cases](/home/birdy/projects/fdb-go/pkg/recordlayer/store_api_test.go:485) omit valid unknown fields. The [deferred-version regression](/home/birdy/projects/fdb-go/pkg/recordlayer/store_api_test.go:531) directly injects queued mutations/local-version entries rather than exercising versioned `SaveRecord` followed by deletion.

   **Fix:** complete those explicit acceptance cases, preserving pinned read versions, first-attempt commit assertions, cold reopen, and absence of resurrected version keys. Existing green populations do not establish these missing cases.
