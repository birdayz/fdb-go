For ignored options, add a private set to `MetaDataEvolutionValidator` and these public APIs:

```go
func (b *MetaDataEvolutionValidatorBuilder) SetIgnoredIndexOptions(
    options []string,
) *MetaDataEvolutionValidatorBuilder

func (b *MetaDataEvolutionValidatorBuilder) GetIgnoredIndexOptions() []string
func (v *MetaDataEvolutionValidator) GetIgnoredIndexOptions() []string
func (v *MetaDataEvolutionValidator) AsBuilder() *MetaDataEvolutionValidatorBuilder
```

Use set semantics: exact, case-sensitive names; duplicates collapse; nil clears; default is empty. Copy on setter, `Build`, and `AsBuilder`; getters return independent, sorted slices. `AsBuilder` must preserve every existing flag. A built validator never mutates its set.

Move changed-option computation into the evolution validator. Compute additions, removals, and value changes, subtract configured names, then dispatch only the remaining mutable set. Preserve the existing type-specific-handler-then-base sequence.

Java now exposes validation of a caller-supplied changed set. Go has no `IndexValidator` object holding the new index, so the concrete equivalent should be:

```go
func ValidateChangedIndexOptions(
    oldIndex, newIndex *Index,
    changedOptions map[string]bool,
) error
```

Document that this function consumes a mutable set and may remove handled names. It must not recompute differences. The evolution validator supplies a fresh set, preventing validators from mutating configuration or index options.

**Explicitly ignored structural option names are permitted by Java.** Its tests allow ignoring `unique` and selected multidimensional options. Do not introduce an “unignorable structural options” list. Conversely, ignoring one option must not suppress another changed option, or bypass index type, expression, version, record-scope, or primary-key checks. See [Java option regressions:2263, 2417](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/test/java/com/apple/foundationdb/record/metadata/MetaDataEvolutionValidatorTest.java:2263).

For evolution, the authoritative identity is **the old union field number and its corresponding new union field**, followed by validation that record-type keys remain equal. A matching current name or explicit record-type key must not override that correspondence.

Implement one correspondence pass:

1. Read `RecordMetaData.GetUnionDescriptor()`. The current helper searches only for `"UnionDescriptor"` and misses Java’s `Union` fixture and other supported union names.
2. For every old union field number, require a new message field. Build bidirectional old/new descriptor mappings; reject removal, splitting one old descriptor across multiple new descriptors, or merging old descriptors.
3. Recursively validate each matched descriptor pair. Memoize **`(oldDescriptor, newDescriptor)`**, not just the old full name.
4. Derive a complete old-name → new-name map, including unchanged names because existing Go consumers expect them. Apply `disallowTypeRenames` to actual identity-preserving name changes.
5. Use that map consistently for record types, primary keys, index associations, and expression rewriting.

Replace the final name-based `validateMessages` pass with validation through those matched pairs. Today it can skip a renamed descriptor or compare unrelated descriptors during a swap. Preserve the existing field-number, field-rename, deprecation, cardinality, type, and enum checks.

For Go’s unionless extension, use a separate typed-key-first correspondence path only when both schemas lack a union; reject mixed union presence. Preserve the existing string-versus-bytes key distinction. This extension must never replace Java’s union-tag identity.

The builder requires a related fix: resolve every union member using `field.Message()`. Currently an underscore-prefixed field name wins over its actual type reference, defeating Java swaps that retain `_TypeAlpha` while changing the referenced message.

When multiple union fields target one descriptor, keep these concepts separate:

- Default record-type key: smallest matching field number, as [Java RecordType.java:171](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/main/java/com/apple/foundationdb/record/metadata/RecordType.java:171) requires.
- Serialization field: canonical `_TypeName`, otherwise highest field number.
- Deserialization: recognize every matching union tag.

Go currently records only the selected tag at `metadata.go:1408`; [store.go:2177](/home/birdy/projects/fdb-go/pkg/recordlayer/store.go:2177) also accepts only that tag. Both lookup paths need the complete correspondence.

There is another persistence prerequisite at `metadata.go:1398`: a global generated message factory is selected by full name alone. Reuse it only when its descriptor matches the current descriptor; otherwise instantiate `dynamicpb` from the current descriptor. Java’s [DynamicMessageRecordSerializer.java:108, 150](/home/birdy/projects/fdb-go/fdb-record-layer/fdb-record-layer-core/src/main/java/com/apple/foundationdb/record/provider/common/DynamicMessageRecordSerializer.java:108) decodes against current metadata. A same-name schema revision must not silently use an older generated shape.

Preserve Go’s correct `expectedRenamedIndexExpression` loop at line 444: iterate **old** index record types, map each identity, and rewrite against its new descriptor. All participating types must produce the same replacement expression.

Move index record-scope validation before expression comparison, matching Java’s staged failures. For rank scans, add a focused Go API alongside the existing scan methods:

```go
type RankScanBounds struct {
    ScanType           IndexScanType
    RankRange          TupleRange
    IncludeRankAsValue bool
}

func NewRankScanBounds(
    scanType IndexScanType, rankRange TupleRange, includeRankAsValue bool,
) (RankScanBounds, error)

func (store *FDBRecordStore) ScanRankIndex(
    index *Index, bounds RankScanBounds,
    continuation []byte, props ScanProperties,
) RecordCursor[*IndexEntry]
```

Validate both constructor input and struct literals at dispatch: only `BY_VALUE` and `BY_RANK`, including when the flag is false. Require a RANK maintainer and the normal readable-state checks. This follows Go’s existing specialized scan APIs without changing the general maintainer interface.

Inside the rank maintainer:

- `BY_VALUE` uses the existing ordinary scan.
- `BY_RANK` uses the existing rank-to-score-range translation.
- False returns the underlying cursor without additional per-entry rank lookups.
- True maps each entry to a new entry with the same index/key and a singleton rank value.

For extraction, let `g = GetGroupingCount()` and `s = GetGroupedCount()`:

```text
group = entry.Key[:g]
score = entry.Key[g:g+s]
```

Validate the length before slicing. Never use `entry.Key[g:]`, and never remove “PK length” from the tail: primary-key components can overlap indexed columns. Existing `RankForScore` consumes its entire supplied suffix, so introduce a helper that extracts the declared columns before invoking the lookup.

Lookup uses `nullIfMissing=true`. Encode a found rank as `tuple.Tuple{int64(rank)}` and a missing score as `tuple.Tuple{nil}`—not an empty tuple or a pointer. Rank is absolute within its group, including bounded/reverse scans. Keep aggregate insertion-rank behavior unchanged.

Match Java’s snapshot preload and serializable actual rank lookup; scan snapshot settings do not convert the latter into snapshot reads. Use the existing fallible cursor mapping to preserve order, continuations, terminal reasons, close behavior, and errors. A synchronous mapping is sufficient for correctness; Java’s pipeline is an optimization. Instrument the completed scan cursor once.

No update-path or stored-value change is required. Existing rank-index values remain empty.
