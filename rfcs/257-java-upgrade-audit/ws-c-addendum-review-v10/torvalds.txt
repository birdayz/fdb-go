## Findings, most severe first

**1. Low: the nest-into-scalar refusal rests on a false premise, and its class is wrong.**
- Four places say Java's `UnsupportedOperationException` "has no Go type":
  - `key_expression_validate.go:149-151`
  - `DIVERGENCES.md:3121-3123`
  - `CHANGELOG.md:266-267`
  - design `:1727-1728`
- It does have one: `UnsupportedOperationError` at `errors.go:329`.
- The code returns `KeyExpressionError` instead, which is the Go form of Java's `InvalidExpressionException`. So `errors.As(err, &KeyExpressionError)` matches in Go where Java's catch would not.
- The text "This field is not of message type." has not been measured. It is my hypothesis, not checked here, that protobuf-java 4.29.3 (the conformance server's version) appends the field's full name.
- **Fix:** return `UnsupportedOperationError` with a JVM-measured text, pin its class and text, and delete the divergence entry.
- **Related:** `errors.go:295` calls `Query.InvalidExpressionException` "a RecordCoreException". It extends `IllegalStateException` (`Query.java:273`). The SQL code is unaffected, because `ExceptionUtil` maps both to UNKNOWN.

**2. Low: the new comment on `Concat` (`key_expression.go:752-753`) says `Build` refuses one-child composites as primary keys. It does not.**
- `Build` refuses only a key with no columns (`metadata.go:877`).
- So `Concat(Field("id"))` builds, and so does `Concat(Concat(), Field("id"))`, which flattening now produces.
- `ToKeyExpression` (`key_expression_proto.go:60-70`) then writes a `Then` with one child. Both loaders refuse it: `key_expression_proto.go:293-294` and `ThenKeyExpression.java:83-85`.
- Go therefore writes meta-data that neither engine can load again.
- **Fix:** refuse at `Build` (or at `ToProto`) and pin it, or narrow the comment.

**3. Low: the PERMUTED upgrade entry is unsafe (`CHANGELOG.md:346`).**
- `RecordMetaDataFromProto` ends in `builder.Build()` (`metadata_proto.go:374`).
- Stored meta-data that an earlier Go wrote now fails to load, so the store does not open, when a PERMUTED_MIN/MAX index has any of:
  - an absent `permutedSize`;
  - an unparsable one;
  - a negative one;
  - one larger than the grouping;
  - a root that is not a grouping.
- "Rebuild" cannot be done until the option is corrected. The `rankNLevels` entry says exactly that (`:343`); this one does not.
- Only a size Java can parse that is not plain ASCII (for example "٢") needs just a rebuild.
- The entry also over-includes "+2": `strconv.Atoi` already read it as 2.

**4. Low: the new permuted validator runs in the wrong place relative to Java's per-index sequence.**
- Java runs each index's validator before that index's subspace-key `put`, and runs all indexes before any former index (`MetaDataValidator.java:103-105`, `:117-119`).
- Go runs these checks in a different order:
  - subspace-key duplicates (`metadata.go:1284`);
  - former-index checks (`:1295-1311`);
  - added versus last-modified version (`:1320`);
  - only then `validatePermutedIndex` (`:1370-1376`).
- **Example:** a PERMUTED index with no size that shares its subspace key with another index. Java reports "permuted size not specified" in either iteration order. Go reports "Same subspace key…". The difference is deterministic and not declared.
- The atomic and TEXT validators already sit in the same place (pre-existing).
- **Fix:** move the per-index validators ahead of those checks, or declare the order.

**5. Low (test vacuity, measured): three class checks assert a relation instead of a value.**
- `TestBuildRecordTypeChecksAreJavasInNameOrder` (`subspace_key_identity_test.go:903-908`) only requires "exactly one of" the two classes.
- `mut-n6` wraps the key-validation error in a `MetaDataError` with the same text. Every shape stays green, including "a primary key validated before its fan-out". Only `TestBuild_PrimaryKeyReferencingNonExistentField` turns red.
- The same pattern is in `metadata_validate_records_test.go:597` and in `java_parse_test.go:239`, where `MetaDataError` and `NumberFormatError` are interchangeable.
- **Fix:** give each case its expected class.
