## Findings, most severe first

**1. Low (wire): the new heading "Index options other than the vector index's are parsed as Java parses them" (`CHANGELOG.md:318`) is false for `bitmapValueEntrySize`.**
- Go reads it with `strconv.ParseInt` and silently falls back to 10000 on a parse error, on a value ≤0, or on one above 250000 (`bitmap_value_index_maintainer.go:48-52`; the chaos model does the same at `chaos/verify_bitmap.go:55`).
- Java uses `Integer.parseInt` and refuses a value above 250000 with `RecordCoreArgumentException` "entry size option is too large" (`BitmapValueIndexMaintainer.java:100-104`).
- The entry size decides each bitmap key's offset and the value's length (`:198-203`). So "٢" is maintained at size 2 by Java and at 10000 by Go, and a size Java refuses is written by Go.
- It is untracked: `git grep -i "bitmapValueEntrySize\|entry size option"` over TODO, DIVERGENCES, CHANGELOG and the RFC-257 `.md` files finds 0 hits; the control `permutedSize` finds hits in CHANGELOG and ws-c/f/j.
- This is the same gap as v9 Torvalds finding 3.
- **Fix:** convert it to `javaParseInt` plus Java's refusal, or scope the heading and record the divergence.

**2. Low (operational docs): the UPGRADE list (`CHANGELOG.md:336-348`, design `:1798`) leaves out meta-data that no longer builds, and one of its instructions cannot work.**
