**P1 — Former-index cleanup can update persisted state without updating an existing context-shared view.**

At [index_state.go:472](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:472), `setIndexState` updates shared state only when the calling handle already has `indexStateView` attached. However, [store_builder.go:386](/home/birdy/projects/fdb-go/pkg/recordlayer/store_builder.go:386) performs former-index cleanup during opening, before that attachment is required. Cleanup calls `setIndexState(formerName, READABLE)` at [index_state.go:724](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:724).

A valid sequential execution demonstrates the consequence:

1. Start with records present and index `X` DISABLED under metadata v1.
2. In one context, open handle A with v1 and read `X`’s state, establishing the shared view containing `X=DISABLED`.
3. Open handle B with v2, which removes `X`. Former-index cleanup clears the persisted state key, but B’s unattached view means the shared map still contains `X=DISABLED`. Choose metadata with no other indexes or replacement relationships.
4. Open handle C with v3, which reintroduces `X` using a **different subspace key**, with rebuild policy DISABLED. Attachment reuses the existing shared view and discards C’s freshly loaded state at [index_state.go:301](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:301).
5. `MarkIndexDisabled` sees the stale DISABLED value and returns without writing the state key at [index_state.go:254](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:254). The v3 header is committed, although `X` was never built.
6. A cold reopen interprets the absent state key as READABLE. Queries can use the empty index while matching records remain.

No concurrent goroutines or raw transaction mutations are necessary. State-key read conflicts cannot repair this divergence within one transaction.

**Required fix:** ensure every lifecycle state writer updates the context’s authoritative view, including former-index cleanup on newly opened handles. Attachment must not be an optional prerequisite for maintaining that invariant. Add a real-FDB v1→v2→v3 regression with separate handles in one context, asserting the raw state key, shared state, cold-reopened DISABLED state, and scan rejection. The existing former-index regression initializes the same handle first, so it misses this path.
