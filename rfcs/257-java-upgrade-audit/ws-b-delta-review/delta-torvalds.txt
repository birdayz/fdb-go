**[P1] Former-index cleanup can leave the shared transactional state stale, causing an unbuilt index to become READABLE.**

At [index_state.go:472](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:472), `setIndexState` updates the shared view only when the calling store has already attached to it. However, opening a new handle loads its local state without attaching, then performs former-index cleanup at [store_builder.go:386](/home/birdy/projects/fdb-go/pkg/recordlayer/store_builder.go:386). That cleanup calls `setIndexState(formerName, READABLE)` at [index_state.go:724](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:724).

Consequently, it clears the persisted state key while leaving another handle’s existing context view unchanged. Later attachment at [store.go:178](/home/birdy/projects/fdb-go/pkg/recordlayer/store.go:178) reuses that stale view.

A concrete, sequential sequence using ordinary APIs:

1. Start with a nonempty store containing DISABLED index `I`. Open metadata v1 and read `I`’s state, establishing the context view.
2. In the same context, open v2 that drops `I`. Former-index cleanup clears its persisted state key, but the shared view still contains DISABLED.
3. Open v3 that adds `I` again with a **different subspace key**, using a rebuild policy returning DISABLED. These are valid successive metadata evolutions.
4. `MarkIndexDisabled` reads the stale DISABLED value and takes its [unchanged-state return](/home/birdy/projects/fdb-go/pkg/recordlayer/index_state.go:254). It never writes the new index’s DISABLED state.
5. Commit. A fresh context sees the absent state key as READABLE, although the new index was never built over the existing records. Queries can silently omit records.

This requires neither concurrent goroutines nor raw transaction writes. The existing former-index test initializes and mutates the **same handle**, so it misses the unbound-handle path.

**Required fix:** attach the context’s authoritative state view before metadata reconciliation can mutate state, and make former-index cleanup update it consistently with persisted mutations. Preserve lock ordering. Add a real-FDB drop/readd regression checking the shared view, raw state key, and cold reopen; the unbuilt index must remain DISABLED and unavailable to queries. This finding is source-derived; I did not execute a reproducer.
