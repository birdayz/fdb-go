## HIGH
**1. The restore's CHANGED exemption is unsound across two histories (design :648-669, :687).**
- Rule (iii) skips any index whose last-modified version H raised, saying it "is rebuilt on open". Java's validator requires only old < new for that index (`MetaDataEvolutionValidator.java:645-660`; Go `:707`). The bound `newLastModified > oldMetaData.version` exists only for NEW indexes (`:549`).
- Within one history the carry makes that bound true. Two independent histories do not.
- Example: fresh v1 has I at last-modified 2 and metadata version 3; the old (t,3) has I at last-modified 3 with a different root and metadata version 4.
  - (i) admits it, (ii) passes, and (iii) skips I.
  - A v1-bound store (header 3) is repaired onto (t,3). The open rebuilds only indexes above the header, and I's 3 is not above 3, so v1's entries are read under (t,3)'s root. That is a silent misread.
- **Fix:** exempt a raised index only when H's last-modified version exceeds L's metadata version; otherwise require EQUIVALENT. Test that case.
- **It also contradicts itself at step 1.** Check (i) uses "the rebind validator's options (`fdb_store_catalog.go:352-353`)", which are only no-version-change and literal-carrier (confirmed at `:352-353`). `allowIndexRebuilds` arrives in step 3. So "a v1 whose index (t,3) raised and changed, admitted" is refused at step 1 with "last modified version of index changed".

## MEDIUM
**2. A union both builds chose, with framings that disagree, loads silently on the ordinary path (:2231-2236).**
- The pre-upgrade loader took UnionDescriptor, then RecordTypeUnion, then a usage=UNION message (`e48f5b496:metadata_proto.go:790-813`), and framed EVERY union name-first (`e48f5b496:metadata.go:325-335`).
- Today's loop is type-first (`metadata.go:394-401`), and `refuseAmbiguousLegacyUnion` returns nil when UnionDescriptor is absent or is the union found (`metadata_proto.go:477-479`).
- So a `_X` typed by a nested `Outer.X` (or an imported `pkg.X`) keeps the record-type name X, still matches the stored RecordType entry, and loads under another descriptor.
- v12 refuses this only on the edited route. The load needs the same field-by-field framing refusal.

**3. R1's reservation enforcement can be bypassed (:2297-2306; DIVERGENCES).**
- The check compares only against the stored version's `reserved`.
- One save drops the reservation (nothing refuses that); the next reuses the number, and it is admitted.
- A message rename also escapes "a message the old version also defines".
- **Fix:** check each new field number against every archived version's fields at the history key, paired by the validator's correspondence.

**4. `CreateTemplate` puts the `v′ <= latest` refusal "first" (:1620-1630, :994).**

- With the new check first, an exact duplicate becomes INVALID_SCHEMA_TEMPLATE. **Fix:** order the duplicate check first.
- The refusal below latest and the relational validator are now library-API divergences from Java's `createTemplate`, and section 9 does not declare them. The comment at `fdb_template_catalog.go:120-128` says the opposite.
- ":10-11/:1629 no writer stores a version at or below the latest" is false: the restore does.
