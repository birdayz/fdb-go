## HIGH
**F1. The restore's check (iii) is unsound, and its validator options contradict the merge order** (`:657-668`, `:687`, `:2571`).
- Check (i) borrows the rebind's options, which on this tree are no-version-change and literal-carrier only (`fdb_store_catalog.go:352-353`).
  - Under those options the validator refuses any change of last-modified version (`metadata_evolution_validator.go:697-699`).
  - So step 1's planned test "an index (t,3) raised and changed, admitted" fails.
- From step 3, `allowIndexRebuilds` joins those options (`:1724`). The validator then returns early whenever the old last-modified version is lower (`:707`; Java `:657-662`), with no floor.
- Check (iii) exempts any such index as "rebuilt on open". But a store bound to L rebuilds only indexes whose last-modified version exceeds its header, and the header is at most L's metadata version (`store_builder.go:395`).
- So an index whose version satisfies L.lmv < H.lmv ≤ L.md, with a different predicate, passes all three checks and is never rebuilt.
  - DDL-built histories reach this whenever the carry gives a CHANGED and a NEW index the same version.
- **Fix:**
  - state the restore's options explicitly;
  - require EQUIVALENT unless H.lmv > L's metadata version (storage v11's wording);
  - test that interval.

## MEDIUM
**F2. A union both builds chose loads silently when its two framings disagree.**
- The design itself says such a union's framings "must agree… no single framing is the records'" (`:2231-2235`), but only the edited route refuses it.
- Shape (d) fires only for DIFFERENT messages (`:1978`). So the same file without a (c) fault LOADS, type-first.
- The pre-upgrade loop was name-first whatever the usage option (`e48f5b496:metadata.go:330-358`).
- Concrete case: a usage=UNION UnionDescriptor with `_X` typed by a nested `Outer.X`, and a stored RecordType X. It loads in current Go and in Java, and rows written by pre-upgrade Go are parsed as `Outer.X`.
- **Fix:** extend the (d) refusal, on load and in `SetRecords`, to a found union that the pre-upgrade build also chose whenever the name-first replay differs by name or by descriptor. Pin it on both engines. This is a source hypothesis, not measured.

**F3. The as-framed retyping is visible to holders of the kept union** (`:2262-2268`).
- The retyping edits the union message itself. Record types holding that message encode their nested bytes by its DECLARED types.
- Toward UnionDescriptor:
  - R1 removes only the other candidate's holders (`:2290`);
  - with a UnionDescriptor holder and a scalar `_T`, step (iii) forces the edit to `T _T`;
  - the validator then compares the retyped copy against the edit, finds them equal, and admits it;
  - the holder's bytes are re-read under another wire type.
- Toward the target's choice with the holder kept, the same retyping refuses a valid edit.
- Also, the validator pairs union fields by NUMBER (`metadata_evolution_validator.go:325`; Java `:201-202`), not "by declared message type" as `:2256-2257` says.
- **Fix:** synthesise the as-framed union as a separate message nothing references, declare the holder-plus-disagreement shape routeless, and test it.

**F4. The reservation's enforcement can be bypassed** (`:2297-2305`, the PENDING DIVERGENCES entry).
- It checks only the immediately previous version. Version k+1 drops the reservation and version k+2 reuses the number: both are admitted.
- It also matches messages by name, so a record-type rename, which the validator admits, sidesteps it.
- **Fix:**
  - make reservations monotone;
  - pair messages as the validator pairs them;
  - test both bypasses.
