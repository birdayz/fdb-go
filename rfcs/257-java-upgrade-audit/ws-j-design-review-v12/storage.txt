## HIGH
**1. The restore's check (iii) admits a foreign index change that no store rebuilds** (design `:663-668`, test `:686-687`).
- Under `allowIndexRebuilds`, the validator returns early once H's last-modified version exceeds L's (Java `MetaDataEvolutionValidator.java:657-662`, Go `metadata_evolution_validator.go:707`). Nothing requires that version to exceed L's *metadata* version.
- A store rebuilds only the indexes whose last-modified version is above its header. Within one history a raised version always clears that bar; across two histories it need not.
- Example:
  - L is a fresh v1 at metadata version 10, whose index i has last-modified version 2.
  - H is the old v3 at metadata version 12, whose i has last-modified version 4 and a changed predicate.
  - The restore admits it.
  - A later `RepairSchema` rebinds stores bound to L (header 10), which keep L's entries under H's predicate.
  - That is exactly the hazard the restore exists to prevent. Storage v11 #3 asked for "above the lower version's metadata version", and v12 did not adopt it.
- Check (i) also cites today's options (`:658`, `fdb_store_catalog.go:352-353`), which lack `allowIndexRebuilds`. Under those options the planned test "raised and changed, admitted" fails instead.
- **Fix:**
  - State that (i) runs with `allowIndexRebuilds`.
  - Require every shared index that is not EQUIVALENT to have H's last-modified version above L's metadata version.
  - Test a raise to at most L's metadata version, and expect a refusal.
  - Apply the same floor to R2 (`:2318`) and test it there.

## MEDIUM
**2. R1's reservation can be released** (`:2296-2303`, and the DIVERGENCES PENDING entry).
- The check compares only against the previous version's reservations. Save n+1 can drop `reserved 5`, and save n+2 can then add field 5. Both pass, and the removed holder's bytes are re-read as the new field.
- It also matches messages by name. The validator pairs messages by descriptor and allows type renames (Java `:355-378`; `:252-253` says a descriptor's name "isn't checked"), so renaming the message escapes the check in a single save.
- **Fix:** pair messages as the validator pairs them, refuse a dropped reservation (or check against every archived version), and test both paths.

**3. The direction rule misses the pre-upgrade loader's framing.**
- The pre-upgrade loader framed *every* union it found name-first (`e48f5b496:metadata_proto.go:249-250` → `metadata.go:346-350`). The last union field of a type also won that type's implicit record-type key (`:366-374`).
- v12 treats only a usage=UNION message named UnionDescriptor as both builds' choice (`:2231-2232`). A usage=UNION or RecordTypeUnion union with no UnionDescriptor is therefore framed type-first. A scalar `_T` in it is dropped from the as-framed side, so an edit that removes or retypes it is admitted over T's stored records.
- The four shapes of 4c (`:1970`) omit three more cases:
  - a found union with a scalar `_T` stops loading, and no migration arm covers it;
  - `_X` typed Y (or `Outer.X`), where both framings build, loads under the wrong descriptor silently;
  - two union fields of the same type with implicit keys move the key from the last field to the smallest, silently.
- **Fix:** define the pre-upgrade choice as `findUnionDescriptorName`'s result, and treat a union both loaders choose as both builds' choice. List these shapes, refuse or declare each, and pin them.
