## Design decisions and implementation boundaries

The upgrade is a coordinated port, not a pin-only rollout. Every source-derived
requirement must have one owning workstream and a retained executable regression.
Existing approved Go-only read-side extensions survive; shared behavior and all
persisted bytes follow the target. An absent baseline subsystem is identified as
a dependency, not declared implemented or dismissed because it is large.

### WS-A — Regeneration safety and recursive structured promotion

Implement the following as the first correctness milestone after design ACK:

- Preserve `PStoredQuery` messages through metadata load/build/save, including
  names, SQL, temporary functions, field presence and unknown bytes. Follow the
  existing defensive protobuf cloning on both sides of the model boundary.
  The later public stored-query model must use this same authoritative data;
  opaque preservation alone does not complete the stored-query feature.
- Port Java's structural promotion mechanism: compute coercions by source and
  target types; recurse through record ordinals and array element types; select
  primitive operations by declared types; rebuild against the target descriptor.
  Preserve absent nullable fields and the difference between NULL and an empty
  repeated field. Rebind nested record/enum descriptors to the target repository.
  `MessageHelpers.coerceObject/coerceArray/coerceMessage` and `PromoteValue` are
  the reference, not an implicit CAST shortcut or runtime-number guessing.
- Array reconstruction retains its declared element type and injects promotions
  for each replacement child, as target `LightArrayConstructorValue.withChildren`
  does. Delete the obsolete requirement that the replacements' maximum type
  already equal the retained element type. Still reject incompatible promotions;
  keep ANY and empty/NONE behavior and checked reconstruction diagnostics.
- Keep the descriptor admission checks strict. A reconstructed record must
  actually contain the promoted carriers; changing declared metadata alone is
  insufficient. Preserve explicit FLOAT versus DOUBLE carriers at storage and
  row-domain boundaries and preserve checked QOV/source-layout provenance.
- Give stored vectors explicit coordinate provenance through the HNSW read and
  candidate paths. Access-info entry vectors are in the stored coordinate
  system, even with DOUBLE encoding; raw pre-centroid node vectors are not.
  Decode/transform at the correct storage boundary and use already-transformed
  entry candidates directly. Audit Search, Insert, Delete/replacement, first
  insert, centroid establishment and neighbor selection together. Writes must
  match Java access-info encoding as well as reads. No primary-key special case,
  global transform deletion, increased tolerance, or search-result patch-up.

Implementation shape: keep promotion in the existing Value/type-repository path,
with a declared-source/target coercion tree (primitive operator, array element,
record ordinal children). Checked reconstruction validates that same coercion
relation; evaluation does not use `promoteConstant`'s runtime-carrier guesses as
its specification. `PromoteValue.Type()` returns the actual target, including its
nullability (`PromoteValue.java:278–279`); callers preserving source nullability
must request it explicitly. The plan's existing descriptor bake must include
structured promotion targets, and unplanned evaluation must use the same type
repository machinery, not loosen `rowMessageToProtoValue` admission. Existing raw
map/array API carriers need declared-type traversal and remain separate from the
strict protobuf-backed planned path. No new serialized-plan format is introduced
by WS-A; that remains WS-G.

HNSW candidates must carry coordinate provenance alongside bytes, rather than
infer it from DOUBLE versus RaBitQ tags: canonical node-storage plain bytes are
raw; canonical access-info plain bytes already belong to the current transform.
Previously written Go access-info can violate this invariant; the mandatory
legacy migration below is part of the upgrade, not transparent dual decoding. Propagate that
provenance through greedy descent, layer search, deletion repair and neighbor
selection. First insert, higher-layer replacement and centroid establishment
write the transformed, unquantized entry vector as Java does; promotion of an
existing stored node to entry point preserves that node's representation after
lifting any raw bytes. Encoding access-info with the ordinary node quantizer is
not correct. Metadata adds field 16 to the existing preservation carrier and its
Build slice copy plus both defensive proto-clone boundaries, without publishing
a second public stored-query model.

#### Preparation and mutation ownership

Prepare the declared-type coercion tree before evaluation; never cache a tree
lazily on a shared Value. The prepared state owns defensive copies of the source
and target type graphs, including nested field names/ordinals, nullability and
enum members. The public `Child`/`Target` fields remain source-compatible, but
are not mutable configuration for an already prepared node: preparation records
the child identity, and evaluation/finalization reject changed child identity or
source/target type drift with a typed error before evaluating that child. A
caller wanting a different child uses checked reconstruction, which recomputes
the relation and never carries a stale source-specific tree across the rewrite.
Mutation concurrent with evaluation is not supported; concurrent read-only
evaluation is required and race-tested.

The normal constructor prepares eagerly, including any standalone structured
target descriptor through the existing `TypeProtoRepository`. A checked factory
returns admission errors to checked reconstruction; the existing pointer-returning
factory retains such errors for evaluation rather than adding new panics. Direct
struct literals must be prepared explicitly before evaluation; repository-owned
literal construction sites, `WithChildrenChecked`, `map_field_values` and the
simplifier must join that same preparation path. An unprepared literal returns a
typed error, not a per-row descriptor compilation or a lazy write. The plan-cache
miss's existing finalizer rebinds target descriptors to its one per-plan repository
before publication, validating the captured relation and leaving the compiled
coercion immutable. One repository alone is insufficient: registering another type
currently invalidates its compiled file while retaining earlier descriptor caches.
Replace interleaved registration/stamping with collection, registration, sealing,
then binding. Collect every reachable constructor and promotion target through the
existing plan/value walk, retaining the write-fed constructor exclusion. Register
the complete synthesizable closure, compile a single final descriptor graph, seal
it against new types, and only then bind constructors and promotions. A sealed
repository permits lookups of registered types but returns a typed error for a new
type; it never invalidates or recompiles its graph. Standalone structured promotion
preparation registers its whole target closure and seals before binding too.

Registration is transactional: an unsynthesizable root must not leave partial
names/messages behind or poison unrelated roots. Validate candidate closures during
preparation and roll back unsuccessful registration before collecting the next
root. Existing raw fallbacks (including duplicate-name join rows and unescapable
field names) remain supported, while a declared name bound to incompatible valid
shapes remains an error. Preparation-time validation may construct disposable
descriptors; none may escape as bound descriptors. Only the final sealed graph is
published. Existing incremental repository callers remain supported outside this
sealed plan path, but invalidation clears all descriptor memoization; they cannot
be used to promise identity across registrations. Preserve strict cross-repository
copying for genuinely foreign messages, not as a substitute for within-plan identity.

Pin pointer identity between a nested constructor/promotion result descriptor and
its parent's field descriptor with child-first and parent-first discovery, unrelated
intervening registrations, nullable wrappers/enums, and checked reconstruction.
Assert lookup stability after sealing, rejection of late registration, failed-root
rollback, preserved raw-query answers, and concurrent read-only execution. Target
Java collects used types before building its repository (`QueryPlan.java:648–678`;
`TypeRepository.Builder.build/addTypeIfNeeded`), which is the publication boundary
this change restores. A rebuilt value is a new node; no mutation of the old shared
preparation is allowed. Descriptor-less raw map/array values remain raw carriers;
a protobuf input requires a prepared target descriptor and strict source admission.
Computed enum fields need the existing repository's Java enum-definition arm and
row/proto enum-number rebinding, not an unrelated descriptor service.

Pin constructor-input type mutation, direct-field drift, checked source replacement
(including invalid narrowing), literal preparation, descriptor identity across a
rebuilt tree, single child evaluation, and concurrent evaluation after finalization.
The tests must assert explicit carriers/types, not equality of two shared derivations.

#### RaBitQ encoder prerequisite

Exact RaBitQ encoding belongs to WS-A, before accepting HNSW write or migration
proofs, not a deferred WS-D dependency. Port the target scalar reduction and
calibration evaluation order: `RaBitQuantizer.java:166–181` takes the square root
of the code-vector dot product and then squares that norm; it does not clamp the
calibration square-root argument. Preserve the target's resulting signed zeros and
NaN serialization behavior rather than introducing a numerical tolerance. Check
normalization, sweep/priority-queue tie behavior, bit packing and floating-point
serialization against the actual Java encoder; mathematically equivalent formulas
are insufficient for persisted bytes. Shared scalar reductions are the reference;
no optional SIMD backend is required.

Retain nonzero, asymmetric Java golden vectors at multiple dimensions and bit
widths, including a norm-rounding case and the negative/zero calibration boundary.
Require literal byte equality, including calibration headers, plus compact and
inline node/edge write → commit → cold-reopen assertions against Java-produced
bytes. The legacy fixture's transformed zero entry proves coordinate provenance,
not encoder fidelity. Each encoder regression must fail with its fix reverted.
Target norm reconstruction needed by these write/search proofs is also WS-A;
GuardiANN signatures and the rest of that backend remain WS-D.

#### HNSW write/cache invariant and legacy migration

Candidates carry coordinate provenance through node writes as well as distance
calculations. A node or inline edge receives the active quantizer applied to a
vector in the active coordinate system (Java `CompactStorageAdapter:239–246`,
`InliningStorageAdapter:283–293`). A transformed DOUBLE access-info candidate
must never be copied verbatim into ordinary node/edge storage under an active
transform. Raw pre-centroid candidates are lifted before encoding; already encoded
candidates retain their encoded representation instead of decode/requantize drift.
`parsedNode` caches contain exactly the persisted node/edge bytes, never an
access-info encoding mislabeled as ordinary node storage. Keeping decoded candidate
vectors separate from stored bytes is essential when the same candidate is used
for access-info replacement and for quantized node/edge writes.

**Legacy Go RaBitQ indexes require disable-and-rebuild before upgraded use.** The
parent writer can commit a pre-centroid node's raw DOUBLE bytes as access-info
while retaining an active centroid/seed: `hnsw.go:1132` returns original candidate
bytes and `:882` persists them. The retained two-insert, centroid-bootstrap,
entry-delete, commit/cold-reopen regression reproduces this against parent
`e48f5b4965543cd4d99b5578356059e12d969c7c`. Its prefix-independent persisted image
is retained with writer/source hashes, not synthesized from a guessed tuple.

There is no writer-version/coordinate tag in Java's access-info tuple. Neither
its location nor its DOUBLE tag proves the history of old Go bytes. Comparing
with a data node is not a general detector: another writer can quantize that
node later while leaving the ambiguous access-info untouched. Therefore do not
add a guessing decoder, automatic in-place repair, or a new incompatible tuple
marker. Deployment must stop legacy Go writers, identify every RaBitQ index they
may have written (including mixed Java/Go histories), call existing
`MarkIndexDisabled` to clear the graph and make public scans refuse it, and rebuild
from authoritative stored records with the upgraded maintainer/online indexer.
Only successful rebuilt READABLE indexes may resume vector reads. Non-RaBitQ
indexes and proven Java-only canonical indexes do not need this migration. An
unknown writer history follows the rebuild path, not the canonical assumption.
This is explicitly **not a transparent rolling upgrade** for legacy Go RaBitQ
indexes; the reader cannot infer or enforce deployment provenance from these bytes.

Retain a real-FDB migration test installing the parent-produced graph beside its
source records, disabling it, proving public read refusal while disabled, rebuilding,
and cold-reopening from both engines. Assert canonical access-info/node/inline-edge
bytes and exact entry self-distance. Also test ordinary canonical Java-written
entries without migration, plus first insert, higher-layer replacement and
post-centroid insert/delete/reopen for compact and inlining layouts. Do not present
successful reads of a manually patched legacy entry as a general migration proof.

References: target `PromoteValue.java:247–273,353–429,478–494`,
`MessageHelpers.java:397,480,579`, `AbstractArrayConstructorValue.java:224–241`,
`RecordMetaDataBuilder.java:245–249`, `RecordMetaData.java:712–720`, and extension
HNSW `StorageAdapter.java:245–254` / `Search.java:231–244`.

Required proof: retained exact regressions; nested record→array→record promotion,
field rename/ordinal and nullability cases, empty/nonempty arrays, invalid
narrowing, input immutability, descriptor identity, Java SQL success, real-FDB
metadata round-trip and both Java→Go and Go→Java HNSW operations. Each fix must
fail its regression when reverted. Numerical closeness does not replace exact
persisted-byte checks.

### WS-B — Storage correctness and metadata lifecycle

- Sliding-window insertion checks the tracked entry before changing count or
  boundary. Existing in-window entries refresh the delegate; overflow entries
  leave it alone; a tracked entry without a boundary is corruption. Remove the
  preemptive-delete mechanism rather than layering another workaround on it.
  Port both build-before-write and write-before-build/replay contracts.
- Store deletion reads the header serializably, invalidates the metadata-version
  stamp for cacheable or malformed headers, always marks state dirty, and clears
  the store transactionally. Missing/noncacheable headers need no stamp bump.
  Exercise cached opens and deletion in both commit orders, including recreate.
- New/changed indexes declaring replacements initialize DISABLED irrespective
  of rebuild policy. Retire an existing readable index only when every replacement
  is READABLE, not READABLE_UNIQUE_PENDING. Integrate retirement with state/commit
  lifecycle; an extra metadata-version change must not be required.
- Port ignored-index-option configuration as a copied, default-empty set. Remove
  only those options before type-specific validation; never globally relax
  structural option checks. Preserve the already-correct old-descriptor loop and
  close record-identity rename/swap/name-reuse cases with the target regressions.
- Include rank in scan entry values only when requested; derive absolute rank
  from grouped score columns, excluding the appended PK. Default scan and stored
  rank-index bytes remain unchanged.

Ownership/evidence: record-storage W3, W6–W8, W11. Proto-editor enum handling is
an explicit pre-existing editor API dependency, not a nonexistent call-site fix.

### WS-C — Persistent pending writes and format 15

Port the full queue and indexer protocol before accepting/producing state 4:

1. Versioned protobuf `Any` payloads, exact type URLs, split entries, incarnation
   and versionstamp order, timestamp, little-endian atomic size counter, and
   row/byte-limited continuations. Reject malformed, future-version and wrong-type
   entries explicitly. Snapshot scans/capacity checks coexist with per-cleared-entry
   read conflicts and serializable emptiness checks.
2. Maintainer-specific capability, serialization and replay, including ordered
   UPDATE and computed-prefix DELETE_WHERE operations. Sliding-window wrappers
   preserve enqueue-time filtering and delegated delete/insert payloads. Do not
   enable queues on all value indexes merely because a Java test helper does.
3. Queue eligibility requires explicit request, supported maintainer, no record
   version columns, format at least 15, and non-mutual build. Otherwise use ordinary
   write-only maintenance. A persisted resumed build retains its state; mutual
   indexing cannot continue an already queued build.
4. Drain/replay precedes removal; readable closeout drains, checks emptiness and
   changes state in one transaction, conflicting with writers in both commit
   orders. Register heartbeat commit checks on every drain/merge transaction,
   including retries and the last exhausted batch. Carry a stable session ID.
5. Preserve target overflow semantics (fail the write or commit-check disable),
   soft concurrent capacity, cleanup of queue/counter/build state, and configurable
   closeout retries. Defaults are 100,000 queued entries and 100 closeout attempts.

**Format decision:** raise maximum support to 15 only with this lifecycle. Keep
Go's established default creation version **14**, independently of the maximum;
Java's default is still 7. An explicit new-format choice activates queued builds.
This preserves the existing rolling-upgrade contract instead of accidentally
raising the default through an alias to the maximum. Old readers cannot join
state-4/format-15 operation. Intermediate experimental queues changed format;
disable/rebuild them before the upgrade rather than reinterpret their payloads.

Ownership/evidence: record-storage W1–W2 and extensions-vector W6. Lucene's distinct
backend remains a pre-existing implementation dependency, with its queue conflict,
retry-heartbeat, clear-quota and suggestion-record requirements retained.

### WS-D — Vector compatibility, GuardiANN and maintenance

- Engine identity governs validation and every access before mutation. Missing
  engine means HNSW; names are case-insensitive; unknown engines and changes to
  persisted engine identity fail. GuardiANN is not SPFresh and cannot enter the
  HNSW storage path. A refusal alone is safety, not feature completion.
- Centralize typed option keys, accepted aliases, duplicate-alias rejection and
  effective parsed configuration comparison. Preserve canonical legacy metadata
  names and target return-vector defaults; stop forcing null vector payloads on
  unquantized scans. Immutable structural options remain immutable.
- Extend compact HNSW layer-zero tuples to preserve optional fourth-field covering
  values through load, neighbor rewrites, deletion repair, cold caches and results.
  Preserve legacy three-field nodes and upper-layer behavior. Port fetch,
  cardinality and quick-start/outward traversal contracts.
- Port full packed-key operation RNG seeding; leave top-layer RNG seeding unchanged.
  Consume WS-A's exact RaBitQ encoder bytes and target norm reconstruction,
  including zero/nonpositive/NaN norm handling; do not defer that prerequisite to
  this workstream. Content signatures make encoder differences storage identity
  bugs, not numerical tolerances. Validate those bytes through GuardiANN's signature
  path as well; optional JVM SIMD is not a requirement to invent a new Go backend.
- Implement GuardiANN root tags 0–7, vector identity, roles, covering metadata,
  SHA-256-derived version-8 UUID signatures, collapsed membership, running
  statistics and persisted lifetime peak. Port assignment, replication, search,
  deletion and stale-candidate filtering, including permitted underfill and
  bounded almost-sorted retrieval rather than claiming an exact global sort.
- Implement split/merge/reassign/collapse/bounce tasks and exact serialization.
  Recheck each fetched task, skip consumed dependencies, remove before execution,
  notify only actual work, and guarantee first-task progress before checking a
  deadline. Fold same-byte replicas only when collapsed membership permits it;
  fresh same-byte nonmembers remain distinct records. Compare evaluator verdict
  before score. Use the final peak-relative merge policy and target defaults;
  preserve one final empty cluster instead of scheduling impossible merges.
- Integrate sparse per-prefix task counts, transactional listeners, negative-count
  disable, backlog signaling, secondary tags 0/1/2, two-transaction lease claim and
  verified drain ownership, delete guard conflicts, session UUIDs, 60-second lease
  handling, and bounded count/time progress. There is no invented global counter
  or rendezvous-hashing substitute. Backpressure follows wrapped typed causes.

Ownership/evidence: extensions-vector W1–W5 and record-storage W4–W5/W15. Keep
pre-existing Go direct-HNSW upsert as an explicitly identified convenience only;
the shared Java insert contract is no-op on an existing PK. Existing shared cosine
zero/clamping and sample-key UUID discrepancies require explicit closure, not a
claim that the upgrade originated them. Do not import upstream recall relaxations.

### WS-E — Shared scalar/SQL semantics and statement execution

- Replace regex-string LIKE pattern representation with the target record of
  nullable pattern/escape values. Use the existing polynomial matcher with the
  target full-string semantics: wildcards cross newlines; `_` consumes one code
  point; escape is exactly one non-surrogate UTF-16 unit, excluding `%`/`_`;
  only escape/percent/underscore may be escaped. Validate an invalid escape even
  when pattern is NULL. Carry explicit absence separately from NUL escape.
  Map 22019/2200B/22025 through typed errors across Value, predicate, SQL and
  INFORMATION_SCHEMA paths. Prefix bounds require sound residual evaluation.
- Decode adjacent string tokens independently before concatenation, preserving
  `'a' 'b'` → `ab` versus `'a''b'` → `a'b` across projections, predicates, DML and
  ESCAPE. Whole-context `GetText()` loses this distinction and is not a decoder.
- Port target nested block comments, whitespace-independent `--`, CR/LF/CRLF/EOF
  termination, unterminated-comment errors and removal of `#` comment syntax.
  Use lexer tokens for cache normalization; do not keep a conflicting handwritten
  comment stripper. Skipped comments must not perturb constant IDs. Quoted
  markers remain data. Port grammar changes through typed visitors, not SQL text
  matching. Preserve already-correct case-insensitive unquoted normalization.
- Implement FROM-less queries as an ordinary one-row relation in the single
  Cascades pipeline, not a special evaluator. Replace old refusal pins with exact
  success/metadata and relational-composition tests.
- Java array construction now rejects NULL elements explicitly with the target
  error. Preserve the owner's approved existing Go read/raw nullable-array extension,
  including its positive SQL comparison pins, rather than removing it in the name
  of this upgrade. Shared stored-array paths must reject unrepresentable NULL
  elements; the detailed design must distinguish that boundary from Go read/raw
  extension paths. Live probes assert each extension outcome independently, not
  cross-engine agreement. Static and runtime rejection
  need separate coverage, including NULL produced by an expression. Keep one-field
  records as records and distinguish unsupported direct nested arrays from supported
  records containing arrays. Bare NULL in IN lists fails with 42809; typed bound
  NULL fails with 0A000. Current nil-parameter SQL-text substitution loses that
  distinction: real typed binding is a required dependency, tested cold and warm.
  NULL predicates remain unknown, not errors. Existing Go IN-subquery support is
  an authorized read-side extension and is not removed.
- Derive variadic nullability by operator: COALESCE uses all-nullable; GREATEST/
  LEAST use any-nullable. Preserve each promoted child's nullability and rederive
  on reconstruction/deserialization. Remove the separate blanket nullable override
  in scalar Value typing. Shared COALESCE evaluates all children as Java does;
  Go-only IF and other unrelated short-circuit contracts do not change. All-untyped-
  NULL and arity admission are explicit shared contracts, not inferred from helper
  tests. IN-list syntactically bare NULL and typed NULL expressions remain distinct.
- Statement snapshot reads apply only to SELECT and EXECUTE CONTINUATION and
  must be supplied again on resume. Connection isolation stays serializable.
  Reject snapshot mutation/DDL/COPY continuation with 0A000; executor DML guards
  run before child consumption, including dry runs. Prove real-FDB RYW/conflict
  behavior rather than merely inspecting the option value.

Ownership/evidence: build-docs W4–W7; cascades W1–W2/W11; relational W1–W3/W10.
Each changed error/result expectation gets its causal upstream reference. Shared
non-string function argument errors use 22F00, including LIKE. Statement options
move to SELECT/DML/EXPLAIN/EXECUTE boundaries; statement EF_SEARCH is removed,
window EF_SEARCH remains. Snapshot choice must not leak through a cached plan;
real-FDB tests include a reader-side write so conflict behavior is observable.

### WS-F — Planner scheduling, explicit readers and properties

- Conditional rule chains advance only on no progress, not on no match. Progress
  includes yielded expressions and requirement-triggered scheduling. Validate
  compatible matcher/root/pruned-input characteristics, union dependencies, honor
  wrapper and inner-rule enablement, and terminate a stale chain. Schedule
  pruned-input rules after child cost optimization with task-stack ordering.
- Use the target decorrelate→simplify and merge→pushdown chains. Derive child
  mergeability partitions; FinalizeExpressions yields their cross-product, not
  the unchanged expression. Merge uses those partitions; predicate pushdown
  handles every eligible leg in one result and removes only successfully pushed
